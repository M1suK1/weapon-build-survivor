## 1\. 装填与库存（需求 1、2、5）

### 1.1 现状：三条自动路径

|触发|代码|现在的行为|
|-|-|-|
|模块寿命烧到 0|`\_fire()` burn 循环 `game.gd:1074-1084`|`sl\[i] = null` 后立刻 `\_refill(i, w)`，从库存拿同 id 补上；没方案时甚至自动挑「整板出力最高」|
|合成装置出件|`\_craft\_tick()` → `\_install(k)`（`game.gd:2667`）|自动装到整板出力最高的格子，装不下才进库存|
|地上捡到模块|`pickup.gd:31` → `add\_module()`（`game.gd:2416`）|找第一个空格直接塞，否则进库存|

### 1.2 改法

1. **合成出件**：`\_craft\_tick()` 里 `\_install(k)` 改成：`if autoplan or bot: \_install(k) else: \_add\_inv(k, 1)`。人类永远只进库存，**没有开关**；bot 的自动装板保留，回归曲线不断。
2. **地上捡到**：`add\_module(mid)` 改成：`if autoplan or bot: \_install(mid) else: \_add\_inv(mid, 1)`。人类永远只进库存。
3. **烧空补料**：保留 `\_refill`，但只由新开关 `auto\_fill` 控制，人类默认 `false`：

   * 关闭：`sl\[i] = null` 后不补；`weapon.plan\_saved\[i]` 保留，格子画虚线幽灵框 + 半透明模块名，表示「按方案缺 X」。
   * 打开：恢复旧行为（从库存按 `plan\_saved` 补）。
   * bot / `playtest` / `autoplan` 强制 `true`，回归曲线不被这次改动打断。
4. **手动补料保留**：点空格（`\_on\_slot\_input` → `\_refill`）、拖拽（`\_place\_at`）、库存「装到当前武器」（`\_install\_from\_inv`）。`\_install(mid, w, force := false)` 加 `force` 参数，手动路径传 `true`，不受开关影响。
5. **不加控制台命令**：14 条命令表继续冻结（v4 §1.2）。开关只放构筑屏 UI；测试用 CLI 参数 `autofill` / `noautofill`（与 `autoplan` 同级，不算游戏命令）。
6. **开局不受影响**：初始 4 个 `base` 是 `\_ready` 直接写进 `slots`（`game.gd:422`），不走 `\_install`；`game.gd:423` 的注释「之后烧完会自动补」要同步改掉。

### 1.3 手持连续安装（需求 5）

现状：`\_pick\_up(mid)` 把模块拿在手里（`hand\_mid`），`\_place\_at()` 放下一格后 `hand\_mid = ""`，要再点一次库存。

改成：

1. `\_place\_at()` 成功后：若 `\_inv(mid) > 0` 则**保留 `hand\_mid = mid`**，否则清空。
2. 手持时鼠标旁显示「手上：锋锐刃 ×3」，可放格子高亮；左键连续点多个格子 = 连续安装。
3. 右键空白 / `Esc` / 再点一次库存同一行 = 放下手持（`hand\_mid = ""`）。
4. 拖拽路径同样：`\_drag\_drop` 成功后若还有库存，保持手持。
5. **覆盖已有模块时，被覆盖的模块按 §4 销毁**，不退回库存。

### 1.4 UI

* 构筑屏顶部加 `UIKit.button("自动补料：关", …)`，开时金色描边；tooltip 说明「只影响烧空补料；合成/拾取永远进库存」。
* 空格且 `plan\_saved` 非空：格子边框虚线灰 + 模块名半透明 + 寿命位显示「缺料」。
* HUD 左下提示补「补料：手动」当 `auto\_fill == false`。
* `\_pt\_log` 加 ` fill=%d`。

### 1.5 方案草稿与「保存方案」（R1 新增）

**为什么这么做**：R1 已定「增量搭建、丢一个模块不可惜」，所以拆卸不返还（§4）。真正难受的是**战斗中误覆盖会顺手改掉补料规则**——以后自动补料按新方案补，玩家却不知情。所以方案拆成「草稿 / 生效」两份，显式保存才改补料行为。

**数据**

```
weapon.plan\_draft : Array\[String]   # 草稿：板面当前状态，随手改
weapon.plan\_saved : Array\[String]   # 生效：auto\_fill / 幽灵框唯一读取源
```

* 现有 `weapon.plan\[i]` 的所有读点（`\_refill`、幽灵框、`\_eff\_targets` 若有用到）改成读 `plan\_saved`；所有写点（`\_place\_at`、`\_uninstall`、`\_swap\_slots`、`\_refill` 成功后）改成写 `plan\_draft`。
* 也就是**板面一动，草稿就跟**——这部分不改变现有手感，只是多了一份待保存副本。

**保存**

1. 构筑屏顶部、`自动补料` 按钮左边加 `保存方案`：

   * `plan\_draft == plan\_saved`：按钮置灰、文案「方案已同步」。
   * 有差异：金色呼吸描边、文案「保存方案 •」，tooltip 列 diff（最多 5 行，如 `2 号：锋锐刃 → 空`、`4 号：空 → 贯穿弹`）。
   * 点击：`plan\_saved = plan\_draft.duplicate()`；若 `auto\_fill` 开且有库存，立刻按新方案补一遍；`\_toast("方案已保存")`。
2. 旁边加 `还原`（次要按钮）：丢弃草稿，`plan\_draft = plan\_saved.duplicate()`；板面不动，只改方案。
3. `\_ready` 写完初始 4 格后同步一次 `plan\_draft = plan\_saved`，避免一开局就显示「未保存」。
4. 幽灵框在 `plan\_draft\[i] != plan\_saved\[i]` 的格子上加一个小「草稿」角标，提示「保存后才会按新方案补料」。
5. 不加控制台命令、不加 CLI 参数：纯 UI 行为。

**边界**

* 未保存就退出/重开：无存档，全部重来，不需要持久化。
* 保存不消耗模块，只改方案；真正扣库存发生在 `auto\_fill` 补料或手动装机时。
* bot / `playtest` 不显示这两个按钮，且每步操作后自动 `plan\_saved = plan\_draft`（保持回归脚本无感）。

## 2\. 悬浮说明（需求 3）

### 2.1 统一组件

新增一个轻量 tooltip（不引新场景）：

```
var tip\_root: Panel          # 最上层 CanvasLayer 里的浮层
var tip\_title: Label
var tip\_body: RichTextLabel  # bbcode，支持多行与颜色
```

* `\_bind\_tip(ctrl: Control, provider: Callable)`：`mouse\_entered` 显示、`mouse\_exited` 隐藏；延迟 0.25s 出现（防扫过闪屏）。
* 位置跟随鼠标 `+ (16, 18)`，超出屏幕右/下时翻到左侧/上方；`mouse\_filter = IGNORE`，不挡点击。
* 内容由 provider 返回 `{title, lines:\[...], color}`，统一 12–14 号字，最多 8 行。

### 2.2 覆盖范围

|位置|内容|
|-|-|
|库存每个模块行|名称 · 阶 · rate/uses · 效果（如「开火间隔 ×0.92」）· 族内下一阶（名字/效果）|
|武器槽位|同上 + 当前寿命、实际出力、邻居加成（mirror/boost/reson 的当前值）|
|升级四选一卡片|buff 变体（§9）：`名称·品质` · 当前级 → 下一级的效果变化；配方卡：模块名 · 效果 · 合成消耗 · 前置|
|宝箱武器卡|武器名 · 品质 · 射程/间隔/目标/基础/倍率/专属字段 + 「与当前武器对比」的差|
|配方面板节点|模块效果 · 消耗 · 时间 · 前置|
|构筑屏「自动补料」「保存方案」按钮|开关说明 / 方案 diff（§1.5）|

### 2.3 文案来源

模块的效果不再散落在 `note` 字符串：`MODULES` 新增 `effect` 数组（§11.3），tooltip 直接按 `effect` 生成「射程 +25」「目标 +1」「20% 概率 +3 次」这类短句；`note` 只做补充。buff 文案同理从 §9 的族表生成，不手写 96 条 description。

## 3\. 升级经济（需求 4）

### 3.1 现状（先对齐事实）

* `level\_cost()`（`game.gd:2791`）= `round(3 × 1.18^(level-1))`：Lv10 = 13、Lv20 ≈ 70、Lv30 ≈ 365。
* `try\_level()`（`game.gd:2796`）**已经是**「库存总数 ≥ 成本 → 扣库存 → 升级」，不是经验条；`game.gd:3086` 的构筑屏也写着「需要 N 个模块（库存 M）」。
* 你看到的「累计模块点」应该来自升级按钮上的进度 `M / cost`：M 是库存总数、cost 是本次要扣的数量，**升级后 M 会立刻减掉 cost**。如果你实测看到「升级后库存没减」，那是 bug，请在 M4 手测时告诉我具体等级与前后数量。
* 问题在**曲线**：1.18 的指数到 25 级以后陡到不可达——Lv30 单级要 365 个模块，而一局 15 分钟的掉落总量也就 300 上下。

### 3.2 新曲线

分段：

```
Lv ≤ 10：cost = round(3 × 1.18^(Lv-1))
Lv > 10：cost = round(cost(10) × 1.12^(Lv-10))
```

|等级|旧成本|新成本|
|-|-|-|
|1|3|3|
|5|6|6|
|10|13|13|
|15|30|23|
|20|70|40|
|25|159|71|
|30|365|125|
|35|833|221|

* 前 10 级完全不变（成本仍按 ×1.18 涨，Lv10 = 13）；10 级后从 ×1.18 降到 ×1.12，30 级成本约为旧的 34%。
* 新增 `LEVEL\_COST\_SOFT := 10`、`LEVEL\_COST\_GROWTH\_LATE := 1.12`，`level\_cost()` 分段计算；`LEVEL\_COST\_BASE/GROWTH` 保留给前段。

### 3.3 扣料顺序

现状 `try\_level()` 按 `\_ids\_all()` 顺序穷举扣料，可能先吃掉 T3/T4 库存。改为：

1. 先扣 `base`（T1）；
2. 再扣 T2 → T3 → T4；
3. 同阶内先扣「数量最多」的 id。

实现：新增 `\_take\_level\_mat(cost)` 按 `tier` 排序遍历，替换 `try\_level` 里那段循环。

### 3.4 UI

* 升级按钮 tooltip 已有「需要 %d 个模块（现有 %d）」；补一行「下一次 +%d / 再下一次 +%d」的曲线提示。
* 构筑屏等级行（`game.gd:3086`）补「距下一级还差 X 个」。
* bot 自动升级阈值（`game.gd:4289`、`4310`）同步改成新 `level\_cost()` 的倍数，保持回归逻辑。

### 3.5 R2 裁定：后期消耗点从哪来

曲线按 §3.2 保留，不再往陡里调。后期「升级太快、buff 溢出」由下面这些新消耗点吸收：

1. **科技树高阶合成**（§11.4）：T3 = 2×同族 T2、T4 = 2×同族 T3，一条族练到 T4 要吃掉大量中阶模块。
2. **buff 变体更多**（§9）：24 族 × 4 品质 = 96 条独立 1→10 级，每次升级只给 3 张卡，想练满要的等级量本身变大。
3. **宝箱放弃折算**（§6）：放弃武器换模块，是「模块 → 武器」反向渠道。

## 4\. 拆卸 = 销毁（需求 6 + R1）

现状有 **4 条离开板面的路径，全都把模块退回库存**：`\_uninstall()`（`game.gd:2472`）、`\_place\_at()` 覆盖旧模块（`game.gd:2464`）、拖到卸下按钮 / 拖回库存区（`\_drag\_drop()`，`game.gd:3657-3658`）、武器被替换时整枪丢弃（`\_replace\_weapon()`，`game.gd:2050`）。于是「拆下再装」等于白嫖重置寿命。

改成：

1. **右键卸下**：模块直接销毁，不回库存；`plan\_draft\[i]` 清空；toast「已销毁 · 寿命不返还」。
2. **覆盖安装**：旧模块销毁，不退回。
3. **拖到卸下按钮 / 拖回库存区**：同样销毁（这两条现在调 `\_uninstall()`，改完自动跟着变）。
4. **板内换位**（`\_swap\_slots()`）：只是移动，模块与寿命都保留（这条不算拆卸，别误杀）。
5. 武器被替换/丢弃时，板上模块现状就是一并丢弃（`\_replace\_weapon()` 直接 `remove\_at`，没有退回库存）；只需在替换确认文案里写明「旧枪上的模块会一起消失」。
6. **UI 文案**：`recycle\_btn.tooltip\_text`（`game.gd:849`）、拖拽提示（`game.gd:3613`、`3617`）里所有「退回库存」改成「销毁」；右键 tooltip 写「卸下即销毁（寿命不返还）」；操作后 toast 最多每 3 秒一次，防刷屏。

**R1 裁定**：不做返还保底，D1 关闭。理由是增量搭建下丢一个模块损失可忽略。误操作的真实风险（战斗中被覆盖后补料规则被悄悄改掉）改由 §1.5 的方案草稿 + 保存按钮解决：草稿随便改，只有点保存才影响补料。

> 唯一例外是 eco 的「回收」buff（§9.3）：升它之后拆卸有概率返还 1 个基础料。那是花等级买的构筑选择，不是默认兜底。

## 5\. 敌人上限：400 = 250 普通 + 150 重装（需求 7）

现状 `MAX\_ENEMIES := 400`（`scripts/data/enemies\_db.gd`），重装 `BRUTE\_CAP := 50` 且不占普通上限，实际同屏可到 450。

改成：

1. `BRUTE\_CAP := 150`；新增 `NORMAL\_CAP := MAX\_ENEMIES - BRUTE\_CAP`（= 250，固定值，**不要**写成「400 − 当前重装数」——那样重装会被普通怪挤到刷不出来）。
2. 刷新节奏也加快，否则 150 只要 6 分钟才堆满：`BRUTE\_INTERVAL` 20 → 12 秒，`BRUTE\_GROUP\_MIN/MAX` 2–4 → 3–6；wave ≥ 3 起。
3. 普通生成判定改成：`enemies.size() < MAX\_ENEMIES` **且** `\_count\_kind\_normal() < NORMAL\_CAP`。`\_count\_kind\_normal()` 用现有计数器：`enemies.size() - \_count\_variant("brute")`。
4. 四处判定都要改：`\_on\_wave\_start` 的精英（`game.gd:1758`）、`\_spawn`（`game.gd:1776`）、`\_emit\_pattern`（`game.gd:1824`）、控制台 `spawn`（`game.gd:4911`）。
5. 重装 `\_tick\_brute()`：`\_count\_variant("brute") < 150` **且** `enemies.size() < 400`；总数满了就等下一轮。
6. HUD 徽章 `重装 N/150`，>100 变红（原 >30）。
7. F3 面板「重装」行显示 `N/150 · 普通 M/250`。

### 5.1 R3 裁定：性能

v4 实测 400 只 ≈98 FPS，150 重装仍有余量；按 150/250 直接做。若手测掉帧，优先砍 `NORMAL\_CAP`，`BRUTE\_CAP` 不动（重装是需求本身）。风险行已关闭。

## 6\. 宝箱：放弃换模块 + 现有武器（需求 8）

现状 `\_paint\_chest()`（`game.gd:3974`）是 4 张武器卡 + 标题/副标，没有放弃入口；`\_chest\_to\_modules()` 只在 bot 背满时用。

### 6.1 放弃按钮

* 卡片区是 `y=152`、高 `430`（底部 582），下面 138px 一分为二：左侧武器条（§6.2，x=36 → 840）、右侧按钮 `(900, 596)` 200×40「放弃并换模块」，快捷键 `0`。
* 点击后：`chest\_offer` 全部清空，按「品质最好的那张卡」折算模块，直接 `\_add\_inv`（不经拾取动画）：

  * 折算表：`2 + quality` 个 `base`（白 3、绿 4、蓝 5、紫 6、金 7）；wave ≥ 12 时其中一半换成 `add`。

### 6.2 现有武器查看

## 7\. 环绕刃：多片扇叶（需求 9 + R4）

### 7.1 现状

* 伤害：`\_fire()` 每 `interval = 1.80s` 对半径内**所有**敌人各结算一次（`targets = -1`，多目标按分摊公式 `per = dmg×(1+0.1×(hits−1))/hits`）。
* 视觉：`game.gd:1218-1226` 画 2 段固定长度弧，`blade\_ph += delta × 2.2`（只转视觉，不参与判定）。
* 数值：`\_eff\_targets()` 里按 `3 × range / 105` 折算（旧逻辑把环绕刃当「多目标武器」估值）。

### 7.2 新判定

```
每把环绕刃有 petals 片扇叶（基础 3，旋刃 buff 可加，上限 7）
角度 θ\_k = blade\_ph + k × 2π / petals
扇叶 = 从玩家出发、半径 rad、角度宽 petal\_arc = 0.50 rad 的扇形环带
敌人满足：|dist - rad| ≤ 18 且 角度差 ≤ petal\_arc / 2 → 命中
每敌独立冷却 0.25s（存 enemy 上的 blade\_cd），冷却期间不被任何扇叶重复打
```

**R4 裁定：转速降到 1.4 rad/s**（原草案 2.2）。`BLADE\_SPIN := 1.4`，`blade\_ph += delta \* BLADE\_SPIN`——视觉与判定共用同一个角度，转速降了命中频率也一起降，所以单发伤害要相应提高：

* 每次命中 `= \_shot\_power() × 0.45`（原草案 0.35）。
* 不再走 `\_fire()` 开火循环：环绕刃在 `\_physics\_process` 里独立 tick（`\_blade\_tick(delta)`），弹药仍按每 `interval` 扣一次（保持经济不变）。
* 不再套多目标分摊公式（`\_eff\_targets` 对 blade 的特判删掉）：每条命中独立结算。
* 渲染：每片扇叶画成有厚度的刀刃（两段粗线 + 尖端三角），随 `blade\_ph` 旋转；命中时敌人闪白（复用 `e.hit`）。

### 7.3 数值测算（转速 1.4）

单个贴在环带上的敌人，命中频率 = `petals × 1.4 / 2π`（扇叶间隔 1.5s > 0.25s 冷却，不会被冷却吃掉）：

||旧版（1.8s 一次）|新版 3 片|新版 5 片|新版 7 片（满）|
|-|-|-|-|-|
|单敌命中频率|0.56 次/s|0.67 次/s|1.11 次/s|1.56 次/s|
|单发伤害|1.00×|0.45×|0.45×|0.45×|
|单敌 DPS|0.56×|0.30×|0.50×|0.70×|
|5 敌合计 DPS|0.83×（分摊后）|1.50×|2.50×|3.50×|

* 定位变了：旧版是「每隔一阵全场各挨一下」，新版是「贴着转、单体略弱、群怪更强」。环带只有 ±18px，5 敌同时贴住已是上限场景。
* 如果手测觉得单体太软，把单发提到 `0.55`；觉得群怪太强，先把转速降到 1.2 而不是砍伤害（转速是你要的手感旋钮）。

### 7.4 旋刃 buff（`petal`，§9 里的一个族）

* 4 条品质变体，各 +1 片扇叶，阈值：白 10 级 / 蓝 8 级 / 紫 6 级 / 金 4 级（品质越高越早拿到）。
* 基础 3 + 4 = **7 片**（等于 §7.2 的上限，不用额外夹取）。
* 金变体额外每级 +0.02 rad 扇叶宽度（满级 +0.20，0.50 → 0.70）。
* 卡面写「环绕刃扇叶 +1（Lv 4 解锁）」。

### 7.5 模块

`blade` 特化模块仍加半径 +25（倍率问题见 D8）。

## 8\. 弹射与爆炸（需求 10）

## 9\. buff 重构：24 族 × 4 品质 = 96 条独立变体（需求 11 + R5）

### 9.1 现状

14 条 buff（`scripts/data/buffs\_db.gd`），字段 `cat/rar/max/desc`，层数存在 `game.gd` 的 `buffs` 字典（`buffs\[id]`，`\_bl(id)` 读取）；升级池每次从 atk/eco/sur 各抽 1 张 + 第 4 张配方卡，**三张 buff 品质随机混合**。

### 9.2 R5 裁定后的模型

> 「buff 应该是 4 个品质的独立的 buff，每种 buff 都能独立升级，升级上限可以拔高至 10 级」

按这句实现为：

```
一个「族」（family）= 一种效果，例如 攻速 / 穿透 / 旋刃
每个族有 4 条品质变体：白 / 蓝 / 紫 / 金  ← 4 条互相独立的 buff，各自一条等级轨
每条变体独立 1 → 10 级（buffs\[id] = 0..10）
品质只决定「每级给多少」，不决定卡面颜色以外的任何东西
```

举例：`攻速·白 Lv6` 和 `攻速·金 Lv2` 可以同时存在、互不替代，效果叠加。

* 变体 id：`"<族>\_\_<品质>"`，如 `rate\_\_gold`。
* `buffs` 字典的键变成变体 id；老代码里 `\_bl("rate")` 全部改成按族汇总（§9.6）。
* 条目数 = 24 族 × 4 = **96 条**，但只在 `buffs\_db.gd` 手写 24 行族表，运行时按公式展开成 96 条，不手写 96 份描述。

```gdscript
const BUFF\_FAMILIES := {
  "rate": {
    "name": "攻速", "cat": "atk",
    "kind": "mul",              # mul / add / int
    "per":  {"white": 0.006, "blue": 0.008, "violet": 0.010, "gold": 0.013},
    "cap":  0.45,               # 该族总收益上限（夹取用，见 9.5）
    "fmt":  "开火间隔 -%.1f%%/级",
  },
  ...
}
const BUFF\_TIERS := \["white", "blue", "violet", "gold"]
```

* `mul`：每级把倍率乘 `(1 - per)`；`add`：每级加 `per`；`int`：整数阈值族（阈值等级表见 9.4）。
* 品质 4 档用 白 / 蓝 / 紫 / 金（武器是白绿蓝紫金 5 档，buff 少一档，避免和武器品质混淆；要 5 档也能加，D4）。

### 9.4 整数族（int）怎么在 10 级里分配

整数效果（扇叶/穿透/跳数/目标/复生）没法每级都给，用**阈值**：

```
每条变体给固定 +1（复生/护盾等例外见上表），
阈值等级：白 10 / 蓝 8 / 紫 6 / 金 4
即：品质越高，越早拿到那 +1
```

* 好处：白卡不是「垃圾」，它只是慢；金卡不是「更强」，它是「更快」——这样 4 档都有存在意义。
* 需要每级都给东西的整数族（`target`、`petal` 金、`shield`）额外带一条连续量（上表「备注」列），保证中间 9 级不空转。
* 全局总量天然有界：每族 4 条变体 × +1 → 扇叶 7、穿透 +4、跳数 +5、目标 +4，正好落在设计上限内，不需要再夹。

### 9.6 代码改造点

* `\_bl(id)` 保留，返回**变体**等级 0–10。
* 新增 `\_buff\_lv(fam: String, q: String) -> int` 与 `\_buff\_sum(fam) -> float`（按族汇总四档）：

### 11.3 效果数据化

`MODULES\[mid]\["effect"] = \[{"k":"mul\_add","v":0.08}, …]`；`\_weapon\_mods()`（`game.gd:2209-2255`）从大段 `match mid` 改成遍历 effect 累加；`bind` 过滤保留；`spread` 的「霰弹 +2」特判删除。tooltip、配方卡、配方面板都从同一份 `effect` 生成文案。

**顺带修的现存问题（改表时一并做）**：

1. `recycle` 模块的 `mo\["recycle"]` 只被赋值、**没有任何地方消费**（`grep '\\\["recycle"\\]'` 只有 `game.gd:2230`）——它的「20% 概率给相邻 +3 次寿命」目前完全没生效；新表里要么在 `\_fire()` 的 burn 循环里实现，要么删掉该键。
2. `blade` 模块 `note` 写「半径 +25、倍率 +20%」，但 `\_weapon\_mods()` 只加半径（`game.gd:2237`）——按新表统一成只加半径，或补上倍率（D8）。
3. `tempo` 的 `note` 写「上限 +40%」，实际是 `combo` 每层 4%、层数上限 10（`game.gd:1071`）——新表写成「满层 +40%」。

### 11.4 科技树

```
base → add → amp → reson
edge → surge → overload
calib → coolant → cryo
light → belt → feed
pierce → breaker → pierce\_x
extend → multi → spread
recycle → tempo → cycle
focus / charge / blade （特化叶）
```

* 解锁卡只从「前沿」抽：`prev` 已解锁、自身未解锁、特化还需要对应武器在手。
* 配方消耗按族：T2 = 3×base；T3 = 2×同族 T2；T4 = 2×同族 T3；`amp` = 2×`add`，`reson` = 2×`amp`；特化 = 2×对应主族 T4（D5）。
* 代码上 `CRAFT\_COST` 从「按阶」改成「按族」：新增 `MOD\_FAMILY := {id: 族名}` 与 `MOD\_PREV := {id: 前置id}`，`try\_craft`/`recipe\_state`/`\_can\_craft` 的 `\_count\_tier(t-1)` 换成 `\_count\_family(prev\_id)`；`\_auto\_recipe()` 的挑选顺序改成「按族前沿」。
* 配方面板改成族分组行（每行 3 格 + 连线 + 状态点）。

### 11.5 与 buff 变体的关系

科技树管模块（25 个 id，T1–T4 单轨），buff 管 96 条变体（24 族 ×4 品质）——两套体系不重叠：

* 模块是「装到槽位上、有寿命、会烧掉」的东西；
* buff 是「整局永久、按族按品质各一条轨」的东西。

### 11.6 R6 裁定

内容量按 25 模块 + 24 族 ×4 品质全做，不砍「维持」族、不砍 sur 新 buff。

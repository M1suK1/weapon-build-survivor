## 1. P0：升级 / 合成根本不扣库存

### 1.1 现象
- 升级后 HUD「库存」数字不变（截图里等级 3→4 要 9 个、库存 14，按完还是 14）；
- 合成也不吃料：`recipe_state()` 说「需 3 个基础」，点合成后库存一个不少；
- 从库存里点「装入」把模块装到板面，库存数字也没变。

### 1.2 根因（已定位）

`scripts/systems/inventory.gd:24` 的写入接口对负数直接返回：

```gdscript
func add(id: String, n: int = 1) -> void:
	if n <= 0:
		return
	counts[id] = of(id) + n
```

而 `scripts/game.gd` 有 **7 处**把「扣料」写成负数调 `_add_inv()`（`_add_inv` 只是 `inv.add()` 的薄封装，见 `scripts/game.gd:3574-3575`）：

| 行 | 调用 | 用途 |
|---|---|---|
| `scripts/game.gd:2797` | `_add_inv(best, -1)` | `_auto_place_best()` 从库存自动装一格 |
| `scripts/game.gd:2870` | `_add_inv(want, -1)` | `_install_from_inv()` 装入选中的模块 |
| `scripts/game.gd:2886` | `_add_inv(best_id, -1)` | `_auto_plan_fill()` 按方案补料 |
| `scripts/game.gd:3006` | `_add_inv(mid, -1)` | `_place_at()` 手持模块落到格子 |
| `scripts/game.gd:3055` | `_add_inv(best_id, -1)` | `_auto_place_best()` 第二处 |
| `scripts/game.gd:3826` | `_add_inv(prev, -1)` | `try_craft()` 扣合成前置件 |
| `scripts/game.gd:3920` | `_add_inv(String(mid), -take)` | `_take_level_mat()` 扣升级材料 |

7 处全是空操作。真正扣库存的只有 `_take_inv()`（`scripts/game.gd:3578`），全仓只有 2 个调用点（`scripts/game.gd:3710` 买装置、`scripts/game.gd:4847` 合成开工），所以「升级免费」这种致命经济漏洞在 check-only 里完全看不出来。

历史原因：v5 把库存抽成 `scripts/systems/inventory.gd` 时，旧实现是 `counts[id] = count + n`（负数天然成立），新实现改成「只增不减 + 单独 take()」，调用点没跟着改。

### 1.3 修法（改 1 处，7 个调用点不动）

`scripts/systems/inventory.gd:24`：

```gdscript
## n > 0 加、n < 0 扣（负数走 take，避免「写了扣料却什么也没发生」）
func add(id: String, n: int = 1) -> void:
	if n < 0:
		take(id, -n)
		return
	if n == 0:
		return
	counts[id] = of(id) + n
```

同时把 `scripts/game.gd` 里 `_add_inv` 的注释补一句「`n` 可为负，负数即扣」。

### 1.4 回归自检（防止再犯）

在 `_check_data()`（`scripts/game.gd:388`）追加一段临时库存自检：拿一个空 `Inventory` 实例，`add("base", 3)` → `total() == 3`；`add("base", -1)` → `total() == 2`；`take("base", 5)` → `total() == 0` 且不为负。debug 构建打印 `INV OK`。

### 1.5 验收
- 升级后库存立刻掉 `level_cost()` 那么多，不够时按不动（灰态）；
- 合成开工后前置件立刻减少，停工/取消不退（现有语义不变）；
- 从库存「装入」一格，库存 −1；
- 板面拆卸/覆盖仍然**销毁、不回库存**（v5 语义不变，别顺手改了）。

## 2. 装置：槽位限制台数 + 产物直进库存 + 升级只加速

### 2.1 现在错在哪
v6 §5 把「装置背包」做成了**产物暂存区**（`device_bag`，2 格，扩容 50/110/242/532），产物要手点「取」才进模块库存；装置升级是四条线（Lv2+ 提速、Lv3+ 背包 +1、Lv4+ 默认自动、Lv5 双份）。结果是：
- 装置越多、背包越挤，玩家得来回点「取」，操作噪音大；
- 「装置背包」这四个字和「模块背包」撞概念，玩家以为它是放装置的；
- 升级带来的三条副作用和「加速」混在一起，看不出升它到底图什么。

### 2.2 新语义

| 概念 | 含义 | 数量 |
|---|---|---|
| **装置槽位** `device_slots` | 只能放这么多台合成装置；买装置要占一个空槽 | 起始 **2**，上限 **8**，扩容价 **50 / 110 / 242 / 532**（沿用 v6 的非线性价格） |
| 模块库存 | 合成产物**到点直接进这里** | 不限量（受模块背包 6 格约束的是「带在身上的武器 + 模块」，见 §2.4） |
| 装置等级 | **只加速**：`合成时间 × 0.88^(lv−1)`（Lv2 −12%、Lv3 −23%、Lv4 −32%、Lv5 −40%） | 1–5 级，价 30 / 60 / 120 / 240 |

也就是说：v6 的 `device_bag`（产物数组）**整条删掉**，名字让给「装置槽位数」；产物不再中转。

### 2.3 代码改动

### 2.4 一个副作用要说清
模块背包 6 格（`backpack_cap`，`scripts/game.gd:127`）限制的是「身上带几组武器 + 模块」，**不影响库存**。所以「产物直接进库存」后，装置可以一直造，库存会越堆越多——这正是 §1 修好扣料之后需要的：材料有出口（升级、合成、扩容），不会因为背包 6 格卡住产出。

### 2.5 验收
- 开局 1 台装置、槽位 2/8；买第 2 台要空槽，满槽不能再买；
- 扩容一次（50 模块）后槽位 3/8；
- 合成到点，模块库存 +1（不用点任何按钮），装置马上可以接下一个；
- 装置升到 Lv5，同样配方的剩余时间从 5.0s 缩到 3.0s 左右（−40%）；
- 装置页不再出现「装置背包」「取」这类字样。

## 3. 右键：空格子放下、空白处收起

### 3.1 现状
`_on_right_click()`（`scripts/game.gd:1283`）：
1. 控制台开 → 关控制台；
2. 拖拽中 → 取消拖拽；
3. 落在已装的格子上 → 卸下（销毁）；
4. 其它情况 → `_close_topmost()` 关构筑屏。

手持模块时按右键，直接走到第 4 步把屏关了，模块还拿在手上——反馈里说的就是这件事。

### 3.2 新映射

| 位置 | 手持模块 | 空手 |
|---|---|---|
| 已装的格子 | 卸下（销毁，寿命不返还） | 卸下（销毁） |
| **空格子** | **放下**（等价左键点格子，`_place_at`） | 什么都不做（不再误关屏） |
| 空白背景 | **收起手持**：模块回库存 + toast「已收起到库存」+ 清掉手持提示 | 关构筑屏（保留旧行为） |
| 拖拽中 | 取消拖拽（不变） | 取消拖拽 |
| 控制台 / 升级面板 / 宝箱 | 保持现有优先级（先关面板） | 同左 |

`_on_right_click()` 里把「命中槽位」拆成「格子已装 / 格子空着」两路；「未命中」再按 `hand_mid` 分流。`hand_mid` 收起的实现：`_add_inv(hand_mid, 1)` + `hand_mid = ""` + `_refresh_build()` + `_hand_update()`。

### 3.3 验收
- 手持模块 → 右键空格子：模块装上、手持清空；
- 手持模块 → 右键空白：模块回库存（HUD 库存 +1）、屏还开着；
- 空手右键空白：关屏；
- 空手右键空格子：没反应（不关屏、不报错）。

## 4. buff 重做：品级 = 收益档次

### 4.1 先说清楚误会在哪
v6 的实现是「25 族 × 4 品质 = 100 条独立变体，每条各自 1–10 级」，但**同一族四个品质只是同一个效果的 4 档数值**：

```
攻速·白  间隔 −4%/级      攻速·蓝 −6%/级
攻速·紫  间隔 −8%/级      攻速·金 −11%/级
```

点上去除了数字变大，没有任何玩法变化，所以看起来像「只是给同品级的东西加成」。反馈要求：**不同品级的收益本身要不一样**。

### 4.2 新模型：一条变体 = 一组效果（`fx`）

数据结构改成「每条变体带 0–2 条效果」：

```gdscript
"<族>__<品质>": {
	"id", "fam", "q", "cat", "name"("攻速·金"), "rar", "max": 10,
	"fx": [{"k": "rate", "v": -0.11}, {"k": "combo", "v": 0.01}],
	"thr": 5,        # 只有整数族（目标/穿透/扇叶/弹射/护盾/复生）才有
	"desc": "间隔 −11% · 连击 +1%"
}
```

四个品质的**结构**固定下来：

| 品质 | 结构 | 玩法定位 |
|---|---|---|
| 白 | 1 条效果，量小 | 起步铺垫 |
| 蓝 | 1 条效果，量中 | 稳定强化 |
| 紫 | **主效果 + 1 条邻族副效果** | 开始改变构筑 |
| 金 | 主效果最大 + 1 条邻族副效果 | 想围绕它搭 |

读点不用重写：`_buff_sum(k)` / `_buff_mul(k)` / `_buff_int(k)` 改成「遍历已持有变体，把它们 `fx` 里 `k` 相同的项按等级累加」——族名就是键名，现有的 20 多个读点（`scripts/game.gd:2732-2739`、`786`、`831`、`1360`、`1400`、`1730`、`1742`…）全部不用改。

### 4.5 顺带清理
`scripts/game.gd:2739` 的 `mo["mul"] *= (1.0 + _buff_sum("target"))` 是死代码（`target` 是整数族、没有 `per`，永远 +0），删掉，避免以后给它加 `per` 时变成「目标数也加伤害」。

### 4.6 验收

- 同族四条同时持有：攻速间隔按四条叠加，面板显示正确的合计（`白3 · 蓝1 · 紫0 · 金0`）；

- 数值夹取不破：闪避最高 50%、护甲最高 60%。

## 7. 风险与待拍板

**R1（Q1 会立刻暴露旧存档/旧平衡）**：修好扣料后升级、合成第一次真正收费，节奏会明显变慢。这是**修 bug 不是改平衡**，先按真实收费跑一局再决定要不要调 `LEVEL_COST_BASE`（6.0）。

**R2（装置变强）**：产物直进库存 + 槽位可扩到 8，中期材料产出会变高。观察点：10 波前能不能扩到 4 槽；太快的话把扩容价 50/110/242/532 抬到 60/140/320/700。

**R3（buff 副效果跨族叠加）**：紫/金带副效果后，同族四条一起拿会同时推两个键（例如攻速四件都推 `range`）。夹取上限已有，但要实测「攻速金 + 连击金 + 爆破金」会不会把连击推到失控。

**D1（待拍板）** §3 右键空格子的行为：推荐「放下手持（等价左键点格子）」；另一选项是「只做取消手持、不自动落格」。默认按推荐做。

**D2（待拍板）** §4 紫/金副效果是否允许**跨类**（攻击 buff 带生存副效果）。推荐**只跨同大类**（攻击带攻击、经济带经济、生存带生存），本表已按此编排。

**D3（待拍板）** 装置升级价格 30/60/120/240 是否保留（现在收益只剩加速，可能偏贵）。推荐保留，实测后再调。

**D4（待拍板）** §2 是否保留「Lv5 自动默认开」这条便利（它不算收益但省操作）。推荐**删掉**，装置默认就开自动、玩家可手动关。

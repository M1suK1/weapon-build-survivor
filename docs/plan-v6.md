## 1. P0：升级卡一张都不画（根因已定位）

### 1.1 现象
升级瞬间屏幕只剩标题「升级！点卡片 或 按 1–4 选择」和副标题，**四张卡全空**；鼠标点不到、按 `1`–`4` 也没反应，`T` 换卡也没反应。之后每次升级都卡在同一状态。

### 1.2 根因
`scripts/data/buffs_db.gd` 里有三个「只要次数、没有连续量」的族**没有 `per` 字段**：
`pierce`（buffs_db.gd:54）、`ricochet`（:71）、`revive`（:160）。

而 `expand()` 与 `_desc()` 无条件取 `f["per"]`：

- `scripts/data/buffs_db.gd:192`：`"per": float(f["per"].get(q, 0.0))`
- `scripts/data/buffs_db.gd:203`：`var per := float(f["per"].get(q, 0.0))`

`Dictionary["per"]` 在键不存在时抛 `Invalid access to property or key 'per'`，`expand()` 直接中断 → `scripts/game.gd:92` 的 `var BUFFS: Dictionary = BuffDB.expand()` 拿到空表（或半张表）。

连锁反应：
1. `_pick_buff_variant()`（game.gd:3796）遍历 `BUFFS` 为空 → 一张 buff 都挑不出 → `_roll_offer()` 只剩 `{"kind":"buff","id":"rate__white"}` + 配方卡；
2. `_paint_offer()`（game.gd:4822）`var d: Dictionary = BUFFS[String(card["id"])]` 再抛一次 → **循环在画第一张卡之前就中断**，所以只有标题；
3. `_take_card()` 同一行 `BUFFS[id]` 也会抛 → 即使点中卡也进不去，`picking` 永远为 true，游戏卡在暂停。

### 1.3 修法
1. `buffs_db.gd:192` → `"per": float((f.get("per", {}) as Dictionary).get(q, 0.0))`；`:203` 同样改 `.get("per", {})`。
2. `game.gd` 的 `_buff_sum()`（`var per: Dictionary = f["per"]`）改成 `f.get("per", {})`，防止以后再加「纯次数族」时同样炸。
3. 加**启动自检**（只在 `OS.is_debug_build()` 或 `perftest` 下）：`assert(BUFFS.size() == 96)`，并在 `_ready()` 里对每个族检查 `kind == "int"` 必有 `thr`、`kind != "int"` 必有 `per`，不满足就 `push_error` 一行带族名。
4. `_paint_offer()` / `_take_card()` 对 `BUFFS.has(id)` 做兜底，缺卡直接跳过并 `push_error`，不再整块中断。

### 1.4 验收
- 升级面板 4 张卡全部可见、可点；
- `1`–`4` 都能选，`T` 能把配方卡换成 buff，选完面板关闭；
- 连续升 10 级不出现空面板；F3 面板 `buff=N/24` 里 N 随选择增长。

### 1.5 复盘（为什么会漏）
v5 只跑了 `--check-only`（语法/类型检查），它**不执行数据表代码**；`expand()` 这种「载入即跑」的初始化错误只有真跑一局才会炸。以后：
- 数据表加一个 `tools/check_data.gd`（`godot --headless --script` 直接调用 `BuffDB.expand()` / `ModDB.MODULES`，断言数量与必填字段），纳入 `--check-only` 同级的必跑项；
- 我这边至少跑一次「开局 5 秒 + 按一次 U」的无头冒烟（`--headless --quit-after 300` 之类），不算手感测试。

## 2. ESC / 右键 的双绑定

### 2.1 现状（都在 `scripts/game.gd`）
- `_input()`（:1082）按 ESC → `_close_topmost()`；`_close_topmost()` 里 `picking` 时不关（等级卡），否则**直接关构筑屏**。
- `_unhandled_input()`（:1152）还有一段 ESC：`hand_mid != ""` 时先放手、否则关屏——**但事件早被 `_input` 处理掉了，这段永远不执行**。
- `_input()`（:1089）按右键 → `_close_topmost()` + `set_input_as_handled()`；槽位的 `_on_slot_input()`（:2772）里的右键「卸下该格」**永远收不到**。
- 屏幕提示还写着「TAB / ESC / 右键 / ← 返回」，等于明示右键是全局返回。

### 2.2 修法
**单一入口**：删掉 `_unhandled_input` 的 ESC 分支，全部走 `_input` 里的 `_on_esc()`：

```
_on_esc():
  1. 控制台开着 → 关控制台
  2. drag 非空 → 取消拖拽
  3. hand_mid != "" → 放手 + 刷板面（不关屏）
  4. picking（等级卡 / 宝箱 / 替换）→ 宝箱与替换可以放弃，等级卡不响应（必须先选）
  5. 构筑屏可见 → 关构筑屏
```

**右键**改成「上下文优先」：
- 先判断指针是否落在某个槽位（`slot_rects` 已有现成矩形，`_drag_*` 在用）：
  - 落在槽位 → 交 `_on_slot_input()` 处理（卸下 / 放下手持），**不**标记 handled；
  - 落在库存行 → 拿起该模块（与左键一致）；
  - 其它位置 → 才走 `_close_topmost()`。
- 拖拽进行中按右键 = 取消拖拽。
- 屏幕提示改成「TAB / ESC / ← 返回（右键：槽位=卸下，别处=返回）」。

### 2.3 验收
- 手持模块时按 ESC：模块被放下、构筑屏还开着；再按一次才关屏。
- 构筑屏里对某格按右键：该格模块被卸下销毁；对空白处右键：关屏。
- 拖拽中按右键：幽灵消失、拖拽取消。

## 3. 升级曲线 + 自动升级

### 3.1 现状
`_level_cost_at()`（game.gd:3586）：Lv≤10 `round(3 × 1.18^(lv-1))`，Lv>10 `× 1.12`（`LEVEL_COST_SOFT := 10`、`LEVEL_COST_GROWTH_LATE := 1.12`）。
实测量级：Lv1=3、Lv5=6、Lv10=13、Lv30=125。反馈「前期要的模块数太少，升级太快」——开局 3 个模块就是一级，前几波能连升 5–6 级。

### 3.2 新曲线（**D1 待拍板**）

分段：**起价 6，前 8 级 ×1.25，第 9 级起 ×1.09**

| 等级 | 旧 | 新 | 等级 | 旧 | 新 |
|---|---|---|---|---|---|
| 1 | 3 | **6** | 15 | 23 | **52** |
| 2 | 4 | **8** | 20 | 40 | **80** |
| 3 | 4 | **9** | 25 | 71 | **124** |
| 5 | 6 | **15** | 30 | 125 | **191** |
| 8 | 10 | **29** | 35 | 221 | **293** |
| 10 | 13 | **34** | 40 | — | **451** |

实现：`_level_cost_at(lv)` 用两段常量（`LEVEL_COST_BASE := 6.0`、`LEVEL_COST_GROWTH := 1.25`、`LEVEL_COST_SOFT := 8`、`LEVEL_COST_GROWTH_LATE := 1.09`），并在构筑屏曲线行同步写新数字。

### 3.3 自动升级开关（**D2 待拍板**）
- 变量 `auto_level := false`；启动参数 `autolevel` / `noautolevel`（照 `autofill` 的写法，`_ready()` 里解析）；bot/playtest 默认开。
- 构筑屏底部加第 5 个按钮「自动升级：关/开」，HUD 左上角在开启时显示「自动升级」小徽章。
- 判定放在 `_hud_tick()`（每 0.25s 一次）：`if auto_level and not picking and not dead and _inv_total() >= level_cost(): try_level()`。
- 升级后怎么选卡，三选一（**D2**）：
  - **A（推荐）** 只自动扣料，选卡仍弹面板手选 —— 最安全，不替玩家做构筑决策；
  - B 自动选「同品质里当前等级最低的族」，面板不弹；
  - C 自动选「与当前武器模块族最搭的族」，面板不弹。
- 验收：开自动后站着不动，库存够就自动升级；关掉后必须按 `U`。

## 5. 合成装置：独立背包 + 升级

### 5.1 现状
- `devices`（game.gd:192）每项 `{kind, left, total, auto}`，`kind` 是正在合成的模块 id；
- `device_cost()`（:3396）= `DEVICE_COST_BASE × DEVICE_COST_GROWTH^(台数-1) × _buff_mul("device")`，**用基础模块支付**；
- `buy_device()`（:3419）要求 `_backpack_used() < backpack_cap` → 装置占模块背包（6 格），所以「3 台装置 + 3 组模块」就满了，反馈里的「背包 3/6」就是这个原因；
- 产物直接进模块库存，满了装置停工。

### 5.2 改法（**D3 待拍板**）

**A. 装置不再占模块背包**
`_backpack_used()` 去掉 devices 计数（只算武器 + 模块）。

**B. 装置背包（独立）**
新增 `device_bag: Array`（产物暂存）、`device_bag_cap := 2`。
- 产物先进 `device_bag`；满了 → 装置停工（进度冻结），提示「装置背包满」；
- 点 `device_bag` 里的格子 → 取到模块库存（受模块背包 6 格限制，满了不给取）；
- 扩容价格**非线性、50 起步**：`50 → 110 → 242 → 532`（每次 ×2.2，向上取整到 5 的倍数），用模块支付（任意阶，按 `_take_level_mat()` 的阶序扣）；
- 按钮放在「装置」标签页顶部：「扩容到 N 格（要 110 个模块）」。

**C. 装置升级（每台独立）**
`devices[i]` 增 `lv`（1→5），升级消耗模块：

| 级 | 消耗 | 效果 |
|---|---|---|
| 2 | 30 | 合成时间 −8% |
| 3 | 60 | 再 −8%，装置背包 +1（该台专属槽） |
| 4 | 120 | 再 −8%，自动开关默认开 |
| 5 | 240 | 再 −8%，成品有 15% 概率一次出 2 个 |

（价格与效果是首批候选，D3 里定：「只做容量」还是「容量+速度+暴击三线」。）

### 5.3 验收
- 装置页能买装置、扩容背包、升级某一台；
- 造 3 台装置后模块背包仍显示 `2/6`（不被装置占）；
- 产物先进装置背包，点一下才进模块库存；
- 装置背包满时装置停住、进度条不动。

## 7. 模块自己的输出间隔（`out_iv`）

### 7.1 模型（**D4 待拍板**，推荐 S）
现在所有模块都是「武器每开一炮，所有模块各贡献一次 `rate`」，所以模块除了数值没有节奏差别。

**模型 S（自走账本）**：
1. 每个已装模块有自己的 `out_iv`（秒）与 `acc`（已攒产出，0→1）。
2. 每帧：`acc = min(1.0, acc + delta / out_iv)`。
3. 武器开火时：该格本次贡献 `rate × acc`，然后 `acc -= 1.0`（即清零，因为上限就是 1）。
4. 因此：模块吞吐 = `rate / out_iv`（与武器间隔无关）；武器越快，每炮吃到的越少、但开炮更频繁 → **总 DPS 不变，弹药消耗变快**（和现有「快枪更耗弹药」的设计一致）。
5. 为了不改整体平衡，`rate` 按 `rate_new = rate_old × out_iv` 重标定，使 `rate/out_iv` 仍等于今天的 `rate`。**所有 `out_iv = 1.0` 时新旧数值完全等价**。

### 7.2 分族 `out_iv`

| 族 | 模块 | out_iv | 手感 |
|---|---|---|---|
| 网络 | base / add / amp / reson | 1.0s | 基准、稳 |
| 锐化 | edge / surge / overload | 1.4s | 慢而重 |
| 冷却 | calib / coolant / cryo | 0.6s | 快而碎 |
| 弹链 | light / belt / feed | 2.0s | 最慢，省寿命 |
| 穿甲 | pierce / breaker / pierce_x | 1.2s | 稳 |
| 覆盖 | extend / multi / spread | 1.0s | 稳 |
| 维持 | recycle / tempo / cycle | 1.5s | 偏慢 |
| 特化 | focus / charge / blade | 2.4s | 最慢，爆发型 |

### 7.3 改动点
- `scripts/data/modules_db.gd`：每条加 `"out_iv"`，`rate` 按 `× out_iv` 重标；`MOD_ORDER` 不变。
- `scripts/game.gd`：
  - `_new_module()`（:2479）返回值加 `"acc": 1.0`（开局满，第一炮不空）；
  - `_process` 每帧推进每个已装模块的 `acc = minf(1.0, acc + delta / out_iv)`；
  - `_slot_out()`（:2499）在算完共振/镜像/增幅之后，把 `out[i] *= float(sl[i]["acc"])`（新增开关参数 `use_acc := true`，`_drag_drop` 的预览传 `false`，避免预览值随蓄能跳动）；
  - 开火后把参与本炮的每格 `acc = 0.0`（`_fire()` 主循环里、`_burn_slots()` 之后）；
  - `_shot_power_of()` 不用改（它已经走 `_slot_out`）；
  - `_board_total()`（:3383 附近）与 `_theory_dps()` 改用 `Σ rate/out_iv`（稳态口径，不乘 `acc`）。
- 面板：`_rebuild_board` 每格显示 `输出 2.0/1.4s` + 一个 0–100% 的细进度条（`acc`）。

### 7.4 验收
- 装 1 个「轻量片」(2.0s)：`输出 1.2/2.0s`；用手枪（0.7s）打，每炮只吃到约 0.35，但三炮合计与旧版一致。
- 换成狙击枪（2.5s）：每炮吃到满 1 次，伤害与旧版一致。
- 板面每格出现蓄能条，能看出节奏差异。

## 9. 激光环：全屏 + 固定间隔 buff

### 9.1 现状（`scripts/data/weapons_db.gd:40`）
`laser`: 射程 420 / 间隔 **40.0s** / 目标 −1（范围内全部）/ mul 4.00 / base 2.0。

### 9.2 改法
1. **射程全屏**：`range: 420.0 → 1600.0`（屏幕对角线约 1470，1600 保证四角都覆盖）；文档写「全屏」。
2. **固定间隔 buff**：新增族 `laser_iv`（cat `atk`，kind `add`，每级 **−1.5s**，四品质 per 白 −1.0 / 蓝 −1.2 / 紫 −1.5 / 金 −2.0，cap 24s）：
   - 结算：`iv = maxf(6.0, 40.0 - _buff_sum("laser_iv"))`（最低 6s，别变成每帧清场）；
   - `_fire()` 里 `iv` 计算处加「仅 laser 生效」分支；
   - 文案 `tpl`: "激光环固定间隔 −%.1fs"；
   - 该族只在拥有激光环时进池（`_roll_offer` 里对 `laser_iv` 加武器前置判断）。
3. 激光环的「射程 +」buff 收益归零 → 该族在拥有激光环时权重减半（简单做法：抽到 `range` 时若只有激光环就重抽一次）。

### 9.3 验收
激光环一炮清全屏（含四角）；拿到 3 级紫色间隔 buff 后间隔从 40s 降到 35.5s，面板显示 `输出 X/35.5s`。

## 10.5 敌人血量上调（R3 决议）

§5 让装置不再占模块背包后，玩家中后期凭空多出 2–3 格模块位；反馈的处理方向是**加强敌人血量**，不是回收玩家便利。

`scripts/data/enemies_db.gd` 三个常量：

| 常量 | 现在 | 改成 | 说明 |
|---|---|---|---|
| `HP_BASE`（:11） | 1.80 | **2.40** | 全程 +33% 血量底 |
| `HP_GROWTH`（:12） | 1.118 | **1.135** | 每波增长更快（第 10 波 ≈ ×3.13，旧 ×2.72） |
| `HP_LATE_GROWTH`（:14） | 1.045 | **1.050** | 12 波后的二次加速略加 |

合计：第 1 波 ×1.33、第 10 波 ×1.53、第 20 波 ×1.73（同波次对比旧版）。不改速度、数量、掉落；`BRUTE_HP_MULT`（×8）与 `BRUTE_HIT_RATIO`（单发 ≤20% 最大血量）都是按血量算的，跟着自动生效。

验收：同一套构筑下第 10 波清怪时间比 v5 长约 50%；重装仍然「至少 5 发」。

## 10.6 数值显示要带满 buff（UI 反馈）

反馈原文：「UI 优化要在武器和模块显示的数值上计算所有 buff，保证能看到数值在随 buff 数量加强」。

### 10.6.1 武器摘要（构筑屏左栏 + F3 + 悬浮）
每一行都走 `_weapon_mods(w)` 的最终值，不许直接印表里的原始字段：

| 行 | 取值 |
|---|---|
| 射程 | `w.range + mo.range`（含 range 族 buff、增程模块） |
| 间隔 | `w.interval × mo.iv`（含 rate 族 buff、冷却模块） |
| 目标 | `mo.targets`（含 multi/spread、target 族 buff） |
| 单发输出 | `_shot_power_of(w)`（含 power 族、锐化族、网络模块） |
| 合计输出/s | `Σ(rate/out_iv) × mul`（§7） |
| 实测/s | `_actual_dps(w)` |

行尾用「基础值 → 当前值」标出增益，例如 `射程 360 → 487`，让玩家一眼看到 buff 在涨。

### 10.6.2 模块卡（库存 / 配方 / 悬浮 / 板面格）
- 第一行：`输出 2.0/1.4s`（模块自身 `rate/out_iv`，与武器无关）；
- 第二行：`本武器内 3.1/1.4s`（乘上当前武器 `mul`、`mo.mul`、`mo.mul_add`、network 加成），换武器会变；
- 使用寿命也走 buff：`寿命 40 → 52`（`uses` 族）。

### 10.6.3 一处实现
新增 `_eff_num(base: float, cur: float) -> String`（`"360 → 487"`；两者相差 <1% 时只印一个），所有显示点统一调它，避免各写一套。

## 13. 风险决议与已定参数

**R1** `out_iv` 会改变弹药消耗节奏：快枪在同 DPS 下更耗寿命，属于设计意图，但可能让「冲锋枪 + 慢模块」变差。缓解：`out_iv` 只影响产出节奏，不影响每发扣次数（每发仍扣 1）。
**R2** 自动升级不替玩家选卡（D2 取 A），因此不会打乱构筑。
**R3** 装置背包独立后中后期偏强 → **按本节 10.5 直接加强敌人血量**（用户 2026-10-20 决议）。
**R4** 激光环全屏 + 间隔 buff → **按原方案实施，先测再说**（用户 2026-10-20 决议）；保留 `min 6s` 与「只有激光环时射程 buff 减半」两条刹车。

**D1 已定**：起价 6、前 8 级 ×1.25、之后 ×1.09。
**D2 已定（A）**：只自动扣料，选卡仍弹面板手选。
**D3 已定**：装置升级做三线（容量 / 速度 / 出双份概率），价格见 §5.2C。
**D4 已定（S）**：模块 `out_iv` 自走账本 + `rate × out_iv` 重标定。
**D5 已定**：激光环间隔 buff −1.0/−1.2/−1.5/−2.0 秒每级，`cap` −24s。
**D6 已定**：UI 整屏重排（§8.2 坐标表）。

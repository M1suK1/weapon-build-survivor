## 1. 需求 4：从脉冲开火改为搜寻目标开火

### 1.1 现状

`scripts/game.gd:435-461` 的 `_fire()`：每 `interval` 秒，对**射程内全部敌人**各结算一次 `_shot_power()`，`_draw()` 里画一个扩散圆环（`PULSE_DUR = 0.30`）。

问题：这不是「射击」，是「光环」。玩家看不到子弹从哪来、打到谁，武器差异也无从体现。

### 1.2 新开火流程

```
每 interval 秒：
  1. targets = _find_targets(range, n)      # 距离升序取前 n 个
  2. if targets.is_empty(): return          # 无目标不开火、不扣次数（保留现有规则）
  3. dmg = _shot_power()                    # 模块网络单次输出
  4. per = dmg * weapon.target_mult / targets.size()   # 见 §2.3
  5. for t in targets: 结算伤害 + 生成一条 tracer
  6. 扣除每个已装模块 1 次使用次数
```

### 1.3 视觉

- **弹道**：瞬发 hitscan + 拖尾线段。`tracers: Array[Dictionary]`，每条 `{from, to, dur, width, color}`，`_draw()` 里按 `1 - t/dur` 做渐隐，用 `draw_line(from, to, color, width, true)` + 终点画 3px 命中圆。
- **命中共振**：敌人被命中时 `hit = 0.18`（已有机制），保留。
- **差异化妆点**：
  - 冲锋枪：细线（1.5px）、亮黄，0.06s
  - 霰弹枪：5 条从枪口散开的短拖尾，0.10s
  - 狙击枪：粗线（3.5px）、白蓝、0.16s，命中点额外画 1 帧十字闪光
- **删除**：`PULSE_DUR`、`pulse_t`、`_draw()` 里的圆环。脉冲圆环只保留一个用途——见 §2.5 的「射程指示」，改成构筑屏里的静态圈，不再在战斗中扩散。
- **可选（低优先）**：命中飘字。先不做数字飘字，只做线段 + 命中点，避免 240 敌人时刷屏。

### 1.4 落点

| 文件:行 | 改动 |
|---|---|
| `scripts/game.gd:435-461` | `_fire()` 重写为按目标结算 |
| `scripts/game.gd:464-469` | `_draw()` 改为遍历 tracers |

### 1.5 验收

## 2. 需求 1：武器分化

### 2.1 数据模型

把武器从「一个字典」升级为「字典 + 定义表」。`weapon` 保留运行时状态（quality / layout / slots / left），定义表只读。

```gdscript
const WEAPON_DEFS := {
    "pistol":  {"name": "手枪",   "range": 300.0, "interval": 1.00, "targets": 1, "target_mult": 1.00,
                "base_mul": 1.0, "uses_mul": 1.0, "color": Color(0.56,0.70,1.0)},
    "smg":     {"name": "冲锋枪", "range": 200.0, "interval": 0.30, "targets": 1, "target_mult": 1.10,
                "base_mul": 0.35, "uses_mul": 2.0, "color": Color(1.0,0.86,0.42)},
    "shotgun": {"name": "霰弹枪", "range": 160.0, "interval": 0.90, "targets": 5, "target_mult": 1.00,
                "base_mul": 0.50, "uses_mul": 1.0, "color": Color(1.0,0.62,0.35)},
    "sniper":  {"name": "狙击枪", "range": 640.0, "interval": 2.50, "targets": 1, "target_mult": 1.00,
                "base_mul": 2.5, "uses_mul": 1.5, "color": Color(0.72,0.88,1.0)},
}
```

### 2.2 数值表

`P` = 模块网络单次输出（`_shot_power()` 中模块部分），弹药寿命 = `uses × uses_mul × interval`。

| 武器 | 射程 | 间隔 | 目标数 | 单发总伤 | 单目标 DPS | 弹药寿命 | 定位 |
|---|---|---|---|---|---|---|---|
| 手枪 | 300 | 1.00s | 1 | 1.00P | 1.00P | 20s | 基准，无短板 |
| 冲锋枪 | 200 | 0.30s | 1 | 1.10P | **1.83P** | **12s** | 近身高 DPS，弹药黑洞 |
| 霰弹枪 | 160 | 0.90s | 5 | 5.00P（满） | 5.56P（满） / 1.11P（1 个） | 18s | 清堆积王者，单挑最差 |
| 狙击枪 | 640 | 2.50s | 1 | **2.50P** | 1.00P | **75s** | 省弹、安全、清场慢 |

三把新武器的设计意图，正好对应弹药经济的三种解法：

- **冲锋枪**：用弹药换 DPS。12s 寿命意味着你必须持续补料，逼迫走位捡掉落。
- **霰弹枪**：用「目标数」换清场效率。敌人越多越强，单挑最弱 → 强制你留在怪群里。
- **狙击枪**：用「低射速」换弹药安全。75s 寿命几乎不用管补给，但 DPS 与手枪持平且只能一个个点，容易堆到被围。

### 2.3 多目标伤害分摊（这是唯一需要拍板的公式）

三种候选：

| 方案 | 公式 | 结果 |
|---|---|---|
| A 均分 | `per = dmg / targets` | 总输出恒定，多目标只是「分散」，霰弹枪完全等价于手枪，失去意义 |
| B 每目标满打 | `per = dmg` | 5 目标 = 5 倍总输出，直接超模（霰弹枪 DPS 5.5P） |
| **C 折扣分摊（推荐）** | `per = dmg * target_mult / max(targets,1)`，且 `target_mult` 随命中目标数线性补偿到 1.5× | 满 5 目标时总伤 5P，单目标时 1.11P，落在 A 与 B 之间 |

**推荐 C**，具体：`per = dmg * (1.0 + 0.10 * (hits - 1)) / max(hits,1)`，`hits` = 实际命中数（≤ targets）。
- hits=1 → 1.00P（不惩罚）
- hits=5 → `1.4/5 = 0.28P` 每目标，总 1.4P/发 → DPS 1.56P（比手枪高 56%，但只有 5 个目标时才成立）

这样「多目标」的收益是**清场速度**而非纯数值膨胀，且不会出现「1 个敌人也打 5 倍」的荒谬情况。上表 §2.2 的 DPS 按此公式重算：

| 武器 | 单体 DPS | 满目标 DPS |
|---|---|---|
| 手枪 | 1.00P | — |
| 冲锋枪 | 1.83P | — |
| 霰弹枪 | 1.11P | **1.56P** |
| 狙击枪 | 1.00P | — |

冲锋枪仍然是单体最高，符合「高射速」的直觉；霰弹枪只有群体时才强。

### 2.4 品质与武器解耦

现状 `QUALITY_SCHEDULE` 按波次强行升级武器品质（`scripts/game.gd:24`）。改为：**品质属于「具体这一把武器」，由来源决定**。

本轮先保持兼容：开局给「蓝·手枪」，12/20 波不再自动升品质，改为**每波结束时的武器掉落**（见 §2.5）。

### 2.5 武器来源（本轮的最小闭环）

用户原始需求是「精英怪概率掉 + 地图宝箱」。本轮只做**精英掉落**，宝箱留到下一轮（宝箱需要地图系统，成本高一个量级）。

- 每波最后 10 秒刷 1 只精英（HP ×8、速度 ×0.8、体型 ×1.8、不掉普通模块）
- 精英死亡时 100% 掉一把武器（品质随机：白 25% / 绿 35% / 蓝 25% / 紫 12% / 金 3%）
- 掉落物走上去 → 弹出「拾取」提示 → 构筑屏里可以**切换当前武器**
- 已拥有武器列表存在 `weapons_owned: Array`，每把独立 layout / slots / 模块，切换时整套换

> 这一条会让「合成/升级」的模块资源在多武器间分配，是真正把「构筑」立起来的地方。如果本轮想更保守，可以先只做「开局随机武器 + 构筑屏切换已拥有」，不做精英。

## 3. 需求 2：增幅模块

### 3.1 规则

- **阶级**：T2.5，插在 T2 与 T3 之间。名字「增幅」，颜色青绿偏白。
- **数值**：自身 `rate = 0`（不产生数值），`uses = 60`，**不随开火扣次数**（它是被动装置，扣次数会让它比别的模块先死，玩家会觉得莫名其妙）。寿命=60 秒纯时间，或干脆无限（推荐无限，靠占槽位做成本）。
- **效果**：每 `AMP_SEC = 3.0` 秒，从**相邻模块**（曼哈顿 1）中随机抽 2 个（不足 2 个就全抽），标记为「已增幅」；下一次开火时这些模块的 `eff` ×2，随后标记清除。
- **叠加**：多个增幅模块独立抽样；同一槽位被多个增幅选中只生效一次（取 ×2，不叠成 ×4）。
- **不可自指**：增幅不会选中自己，也不会选中其它增幅模块。

### 3.2 结算顺序（关键）

`_slot_out()` 现有阶段是「base → 共振 → 加法/阵列镜像」。增幅必须插在**共振之后、镜像之前**：

```
base(tier rate)
  → 共振（相邻同阶 +50%）
  → 增幅（被选中的槽位 eff *= 2）
  → 加法/阵列（镜像相邻/半径2内的低阶 eff）
```

这样做的收益是：**增幅的 ×2 会被加法/阵列复制一份**，5 槽布局里「增幅 + 加法 + 基础」能形成一次小爆发，构筑有回报。代价是可能一次爆出很高数字，用 §3.3 的上限压住。

### 3.3 上限（防指数）

- 单次开火中，增幅带来的额外输出上限 = `网络原始总输出 × 1.5`。超出部分截断。
- 实现：算完 eff 后，`boost = sum(eff_after) - sum(eff_before)`，若 `boost > raw * 1.5` 则按比例缩回。
- 理由：没有这层 clamp，「4 个增幅 + 加法 + 阵列」在 6 槽金武器上能做出 10 倍爆发，直接把 HP 曲线打穿。

### 3.4 获取

增幅模块不合成，**只能从 T2 合成配方里随机产出**（10% 概率替代加法），或作为精英掉落。本轮先走「合成时 10% 变异」，因为不引入新 UI。

| `scripts/game.gd:374-404` | `_slot_out()` 插入增幅阶段 + clamp |

## 4. 需求 3：自动化合成装置

### 4.1 现状

`try_craft()`（`scripts/game.gd:665`）是瞬时的：按 C → 检查 `inventory[t-1] >= 2` → 扣 2 → `_install(t)`。没有时间成本，也没有装置概念。

### 4.2 设计

**装置位置**：独立「工坊槽」，不占武器电路板槽位。

理由：占武器槽 = 直接 -1/5 输出，在 5 槽时是 20% 的硬砍，玩家只会觉得被罚；而电路板的美感是「网络」，塞一个不产生数值的装置会破坏拓扑。

- 开局 1 个合成装置，wave 15 解锁第 2 个
- 每个装置：2 个任务队列位，串行执行
- 任务 = `{tier, remain}`，投入 2 个 T(n) → `CRAFT_TIME[n]` 秒后产出 1 个 T(n+1)

**合成时间**（越长越需要规划，但不能让人干等）：

| 配方 | 时间 | 对比「升级」 |
|---|---|---|
| 2×T1 → T2 | 8s | 升级吃 3 个模块、瞬间完成 |
| 2×T2 → T3 | 14s | |
| 2×T3 → T4 | 22s | |

这条与「升级」形成清晰对撞：**升级 = 吃 3 个、立刻、加等级；合成 = 吃 2 个、要等、出高阶模块**。玩家库存有限时必须选。

**自动化**：每个装置一个开关「自动补料」。
- 开启后，空闲时自动从**库存**取料（永不碰槽位——槽位是工作区，之前试过自动拆槽导致崩塌）
- 关闭时只能手动投入
- 自动补料优先级：先补队列空位，再按 `T3 > T2 > T1` 选配方（高阶优先）
- 装置与暂停解耦：构筑屏是 `paused`，装置计时必须用 `process_mode = PROCESS_MODE_ALWAYS` 或用 `Time.get_ticks_msec()` 累加，否则「暂停时合成不推进」会让玩家学会挂着构筑屏等时间

**UI（构筑屏底部）**：

```
[工坊] 装置 A  T2→T3  剩余 9.3s  [====      ]  [自动 ✓]
       装置 B  空闲                   [          ]  [自动 ✓]
```

| `scripts/game.gd:665-675` | `try_craft()` 改为「把任务塞进空闲装置」，返回是否成功 |

## 5. 平衡影响与验证计划

### 5.1 必须同步调整的两处

1. **脉冲 → 单目标/多目标是净削弱**。现状脉冲打全场，改后只打 N 个。手枪从「打全部」变成「打 1 个」，DPS 表面不变但**清场能力大幅下降**，波次中后期会迅速堆积。
   - 补偿：`HP_GROWTH` 从 1.115 降到 1.08 试跑；或把 `SPAWN_GROWTH` 从 0.06 降到 0.045。
   - 不要一次动两个，先只降 HP 成长，跑 bot 看死亡波次。
2. **模块寿命压力**：冲锋枪 12s 寿命会让「掉落跟不上」的感觉非常强。若 bot 在 wave 10 前崩溃，调 `uses_mul` 而不是调掉落率。

## 7. 风险与回退

| 风险 | 概率 | 后果 | 回退 |
|---|---|---|---|
| 分摊公式选错导致霰弹枪超模 | 中 | 中后期无脑霰弹 | 公式是单点改动，改 `target_mult` 即可 |
| 增幅 + 镜像爆出天文数字 | 中 | HP 曲线失效 | §3.3 clamp 是硬保险，先写 clamp 再做数值 |
| 合成时间让节奏变拖沓 | 中 | 玩家干等 | 时间表是常量，直接调 |
| 装置占 UI 空间 | 低 | 构筑屏拥挤 | 装置面板可折叠 |
| 多武器让模块库存被稀释 | 高 | 每把武器都不够用 | 本轮先只允许 2 把武器同时持有 |

## 8. 需要你拍板的 6 件事

| # | 问题 | 我的推荐 | 备选 |
|---|---|---|---|
| 1 | 多目标伤害分摊用哪个公式 | **C 折扣分摊**（`per = dmg × (1+0.1×(hits-1)) / hits`） | A 均分（多目标完全无收益）/ B 满打（超模） |
| 2 | 增幅的 ×2 能不能被加法/阵列复制 | **能**（这是构筑深度所在，配 clamp 控制上限） | 不能（更安全，但增幅只是个小加成） |
| 3 | 增幅模块是否消耗次数 | **不消耗**（纯被动，占槽位就是成本） | 消耗（会让它比别的模块先死） |
| 4 | 合成装置占武器槽还是独立工坊槽 | **独立工坊槽**（占武器槽 = 硬砍 20% 输出） | 占武器槽（更硬核，取舍更痛） |
| 5 | 本轮是否做精英怪掉落武器 | **做**（否则多武器没有获取渠道，等于白做） | 只做「开局随机 + 构筑屏切换」，精英留到下一轮 |
| 6 | 是否保留脉冲作为某把武器的特色 | **不保留**（两套结算逻辑并存会让平衡无法推理） | 保留给「激光环」类武器 |

拍板后我按 P1 → P4 顺序做，每个阶段给你截图 + bot 数据。

## 1. 背包、多武器、左侧武器栏

### 1.1 背包

```
backpack: Array[Dictionary]
  {kind: "weapon",     id: "smg", quality: 2, slots: [...], layout: [...]}
  {kind: "fabricator", tier: 3, task: null, remain: 0.0, auto: true}
capacity := -1   # -1 = 不限，先不做上限，但所有入包都走 _backpack_add()
```

- 武器和合成装置**抢同一个背包**，模块不占（模块仍在 `inventory[t]`）。
- 容量暂不限，但代码里必须走统一入口，将来加限制只改一个常量。
- 背包里的武器**不消耗、不开火**；只有 `enabled` 的武器参与战斗。

### 1.2 开关

- 每把武器 `enabled: bool`，默认新捡到的武器为 **关**（避免一捡到就偷吃模块）。
- 关闭时：不开火、不烧模块、模块照样按寿命规则静止（不开火就不扣次数，这是现有机制）。
- 合成装置不需要开关（只有「自动补料」开关，见 §5.3）。
- 开关的作用是**弹药预算**：多把武器同时开 = 多份 `burn/s`，掉落跟不上就会空板。玩家要主动决定「这波开几把」。

### 1.3 左侧武器栏

固定在屏幕左侧，战斗与构筑都显示（构筑时放大、带开关按钮）：

```
┌ 武器 ────────────────┐
│ [✓] 手枪   蓝·4槽     │
│     当前 14.0  理论 14.0│
│ [ ] 霰弹枪 绿·3槽     │
│     当前 11.0  理论 11.0│
│ [✓] 激光环 紫·5槽     │
│     当前 38.5  理论 96.0│
└──────────────────────┘
```

- **当前 DPS** = `_shot_power() / interval`，按板上此刻的真实加成算（脉冲只算已累积的部分）。
- **理论 DPS** = 把该板所有脉冲的加成按**封顶值**（9 跳 = +81）代入再算一次。
  → 两个数拉开距离，说明「板子还在热机」，这是脉冲类模块最好的可读化。
- 关闭的武器灰显，DPS 显示为「—」。

## 2. 武器定义

### 2.1 数据表

`P` = 模块网络的单发输出（不含武器基础伤害）。伤害分摊见 §2.2。

| 武器 | 射程 | 间隔 | 目标数 | 单发倍率 | 单体 DPS | 满目标 DPS | 弹药寿命 | 定位 |
|---|---|---|---|---|---|---|---|---|
| 手枪 | 300 | 1.00s | 1 | 1.00P | 1.00P | — | 20s | 基准 |
| 冲锋枪 | 200 | 0.30s | 1 | 1.10P | **1.83P** | — | **12s** | 弹药黑洞 |
| 霰弹枪 | 160 | 0.90s | 5 | 1.00P | 1.11P | **1.56P** | 18s | 清堆积 |
| 狙击枪 | 640 | 2.50s | 1 | 2.50P | 1.00P | — | **75s** | 省弹、安全 |
| **激光环** | **520** | **2.60s** | **4** | **3.00P** | **1.15P** | **1.50P** | **52s** | 大数字 + 脉冲专属 |

- 激光环的 3.00P 单发是全场最高，但 2.6s 一发，且它**是唯一能用脉冲的武器**。
- 弹药寿命 = `uses × interval`（激光环 20 次 × 2.6s = 52s，很省）。

### 2.2 多目标折扣分摊（沿用 v2 方案 C，但你这次没否，我按它算）

`per = dmg × (1 + 0.10 × (hits − 1)) / hits`，`hits` = 实际命中数。

- `hits = 1` → 1.00P，不惩罚
- `hits = 4` → 每目标 0.325P，合计 1.30P
- `hits = 5` → 每目标 0.28P，合计 1.40P

多目标的收益是**清场速度**，不是纯数值膨胀。

### 2.3 激光环与脉冲

- **脉冲模块只能装在激光环的板子上**；其它武器捡到脉冲会进库存但在构筑屏里标灰「需激光环」。
- **共振由 2 个脉冲合成**，所以共振事实上也变成激光环的专属上阶。
- 理由：脉冲 3s 一跳、每次开火只扣 1 次使用，慢武器（2.6s/发）等于「跳数与开火数比最高」，而激光环的高倍率会把脉冲喂出来的基础值再放大 3 倍——这是设计上唯一让脉冲成立的位置。
- 激光环的来源：精英怪掉落池里独立 15% 权重（其它武器分摊剩下的）。

## 3. 搜寻目标开火（沿用 v2，未改）

每 `interval` 秒：`targets = _find_targets(range, n)`（距离升序前 n 个）→ 无目标则不开火不扣次数 → `per = dmg × mult / hits` → 逐个结算 + 生成 tracer → 扣每个已装模块 1 次。

视觉：瞬发 hitscan + 拖尾线段（冲锋枪细黄 0.06s / 霰弹 5 条短散 / 狙击粗白蓝 0.16s / 激光环环形扩散 0.12s）。删 `PULSE_DUR` 与圆环。

## 4. 模块网络 v2

### 4.1 脉冲（T3，激光环专属）

保持现状：自身输出 0，每 3s 给相邻**主动模块**的基础值 +9.0，叠 9 跳封顶，加成写进对方 `base` 并被加法镜像、被共振按 base 计算。

新增限制：只能装激光环。`_install()` 与构筑屏都要拦。

### 4.2 增幅（T2.5，新定义）—— 这次的核心改动

| 项 | 值 |
|---|---|
| rate（自身基础值） | **5.0** |
| uses | **60** |
| 触发 | **每次开火**，把 5.0 加到**所有相邻模块的最终输出**上 |
| 自身输出 | 0（值全给邻居） |
| 能否被镜像 | **不能**——它加的是 `out`，加法读的是 `eff`，所以加法看不到它 |
| 消耗 | **每发扣 1 次**（`uses 60` → 1s 武器 60s、激光环 156s） |

结算顺序（`_slot_out()`）：

```
base = TIERS.rate + 脉冲加成
  → 共振（相邻同阶 +50%，读 base）
  → 加法镜像（读相邻更低阶的 eff）
  → 增幅（把 5.0 直接加到相邻模块的 out 上）   ← 最后一步，不回流
```

**和脉冲的区别（必须一眼能看出来）**：

| | 脉冲 | 增幅 |
|---|---|---|
| 加到哪 | 邻居的**基础值** | 邻居的**最终输出** |
| 会不会被放大 | 会（加法镜像、共振按 base 算） | 不会（加完就是最终值） |
| 强弱看什么 | 板子的网络密度 | 邻居的数量而已 |
| 适合 | 激光环（多重放大） | 任何板子（网络越烂越有用） |

一句话：**脉冲是「把原料喂肥」，增幅是「直接补一笔钱」**。脉冲在密排板上爆炸，增幅在稀疏板上救急。

### 4.3 加法 / 共振（不变）

加法 T2 镜像相邻低阶；共振 T4 相邻同阶互 +50%。不连锁传播。

### 4.4 模块表汇总

| 阶 | 名称 | rate | uses | 效果 | 可装 |
|---|---|---|---|---|---|
| T1 | 基础 | 1.0 | 20 | — | 全部 |
| T2 | 加法 | 3.0 | 24 | + 相邻低阶基础值 | 全部 |
| T2.5 | **增幅** | 5.0（给出） | 60 | 每发给相邻模块 out +5.0 | 全部 |
| T3 | 脉冲 | 9.0（给出） | 28 | 每 3s 给相邻主动模块 base +9.0 | **仅激光环** |
| T4 | 共振 | 27.0 | 34 | 相邻同阶 +50% | 仅激光环（原料是脉冲） |

增幅怎么来：**2 个 T1 + 1 个 T2（加法）合成**，即配方 `2 基础 + 1 加法 → 1 增幅`，Lv6 解锁。这样它有独立的原料成本，不跟加法抢同一条配方线。

## 5. 合成装置

### 5.1 装置本身

- 装置是**背包里的道具**，用基础模块造出来：

| 装置 | 造价 | 能做的配方 | 合成时间 |
|---|---|---|---|
| T2 装置 | **12 基础模块** | 2×T1 → T2 | 8s |
| T3 装置 | **32 基础模块** | 2×T2 → T3 | 14s |
| T4 装置 | **80 基础模块** | 2×T3 → T4 | 22s |

- 装置**越高级越贵，且不能互替**：T2 装置做不了 T3 配方，想上高阶必须再攒一个高级装置。
- 造价用**基础模块**而不是高阶模块，理由是：基础模块是玩家手上最多、最不心疼的东西；用高阶模块造装置会跟「升级」直接抢命。80 个基础模块在 wave 20 约等于 50 秒的掉落量，是「攒一波换质变」的量级。
- 装置造出来后在背包（= 共享容量），没有数量上限（容量先不做）。
- 构筑屏里多一个「工坊」面板，列出背包里的装置与它们的队列。

### 5.2 队列与时间

- 每个装置 1 个任务位（串行）。任务 = `{tier, remain}`。
- 投入 2 个 T(n) → `CRAFT_TIME` 秒后产出 1 个 T(n+1)。
- 暂停解耦：构筑屏是 `paused`，装置计时走 `PROCESS_MODE_ALWAYS`，否则玩家会挂着面板白嫖时间。

### 5.3 自动补料

- 每个装置一个「自动」开关：空闲时自动从**库存**取料（永不碰槽位）。
- 优先级：能做高阶就做高阶（`T3 > T2`），同阶优先消耗**剩余次数多**的。
- 关掉自动就纯手动，`C` 键 = 「把手头最高可行的配方塞进一个空闲装置」。

## 6. 不做输出上限之后的风险与预案

你在 §「先不做输出上限」这一条上和 v2 的 clamp 方案相反，我按你说的做，但把风险写在这里：

| 风险 | 触发条件 | 预案（都不需要现做） |
|---|---|---|
| 增幅堆叠把单发拉爆 | 6 槽金武器塞 4 增幅 + 加法 + 基础 | 增幅的 5.0 是**不吃网络**的平值，堆 4 个 = 每发给每个邻居 +20，量级可控；真爆了就调 `AMP_RATE` |
| 脉冲 + 共振 + 激光环倍率 | 激光环 3.0 倍率 × 脉冲喂肥的板 | 这是**故意的**，激光环就是「热机越久越强」；HP 曲线跟不上时先降 `HP_BASE` 而不是砍机制 |
| 多武器同时开火 | 4 把武器全开 | 弹药消耗是天然上限（burn 随武器数线性上涨），玩家自己会关 |

## 7. 实施顺序（每阶段可独立验收）

| 阶段 | 内容 | 验收 | 预估 |
|---|---|---|---|
| **A** | 背包 + 武器定义表 + 左侧武器栏（单武器也能跑） | 左侧栏显示开关与两个 DPS；4 把武器可切换 | `game.gd` ~150 行 |
| **B** | 搜寻目标开火 + 弹道 + 删圆环 | 无目标不扣次数；4 把武器手感不同 | ~130 行 |
| **C** | 增幅模块（新定义）+ 配方 | 构筑屏里增幅相邻格输出 +5.0 跳变 | ~70 行 |
| **D** | 激光环 + 脉冲专属限制 | 非激光环武器装不上脉冲 | ~60 行 |
| **E** | 合成装置（造价 / 时间 / 自动 / 工坊面板） | 暂停时仍推进；自动只吃库存 | ~180 行 |

顺序理由：A 是后面所有东西的容器（没有武器列表就无处挂开关和 DPS）；B 是地基（目标数才有意义）；C/D 是纯逻辑；E 最重且最独立。

每阶段跑一次 `-- playtest bot pt=1500` + 两张截图（战斗 / 构筑）。

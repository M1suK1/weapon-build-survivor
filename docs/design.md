## 0. 一句话

> 你不是在「升级武器」，你是在**经营一条弹药供应链**。
> 模块既是子弹，也是升级货币；死在不是血条被打空，而是弹药链断了。

这套游戏最独特、也最必须做对的地方：**武器的伤害不是数值，而是数值的流量**。玩家做的每一个决定（哪把武器、什么品质的槽位布局、插什么模块、什么时候熔解）最终都折算成同一个指标：

```
每消耗 1 个模块，你能打出多少伤害
```

---

## 1. 三层核心循环

| 层 | 时长 | 玩家在做什么 | 失败/收益 |
|---|---|---|---|
| L1 战术 | 1–2 秒 | 走位躲弹幕，武器自动开火，模块燃料在烧 | 被围死 |
| L2 构筑 | 30–60 秒 | 开构建屏（暂停）→ 插模块 / 合成 / 熔解 / 换武器 | 弹药净收入为负 → 慢性死亡 |
| L3 单局 | 15–20 分钟 | 逐波清怪，升级解锁新配方，精英掉武器 | Boss / 死亡结算 |
| L4 元游戏 | 跨局 | 精华 → 永久升级；工坊等级半保留 | 每局起点更高 |

**L2 是核心卖点。** 幸存者类的乐趣在 L1，本作必须让 L2 至少同样有嚼头：
构建屏里有实时数字预览（DPS、模块烧毁速率、净弹药率、预计存活时间），玩家像调参一样拧自己的构筑。

## 2. 数值体系（核心模型）

### 2.1 术语

| 符号 | 含义 |
|---|---|
| `rate` | 模块每秒产出的**数值**（Value） |
| `stored` | 模块当前存量；`storedMax` 为上限，溢出丢失 |
| `uses` | 模块剩余**使用次数** = 剩余可开火次数 |
| `interval` | 武器开火间隔（秒） |
| `mul` | 武器倍率：1 点数值 → 多少伤害 |
| `network` | 从核心槽出发、通过连接可达的槽位集合 |
| `mirror` | 加法模块提供的「镜像复制」系数 |

### 2.2 结算规则

```
每帧：   stored = min(stored + rate * dt, storedMax)
每 interval 秒（且射程内有目标时）：
         raw = Σ(stored of m in network)          // 抽取并清零 stored
         for m in network:
             if m.isAdder:
                 raw += Σ(draw of n in neighbors(m) where n.tier < m.tier)
         damage = raw × weapon.mul × (1 + buffs)
         for m in network: m.uses -= 1
         if m.uses == 0: 模块烧毁，槽位空出
```

三条关键推论：

1. **DPS ≈ Σ(rate)**，与开火间隔基本无关（只要不溢出）。
   → 间隔不改变输出功率，只改变「爆发颗粒度」和「模块烧毁速度」。
2. **模块寿命 = uses × interval**。
   → 间隔越短，烧模块越快。DPS 不变，弹药消耗翻倍。
3. **溢出才损失 DPS**：若 `interval > storedMax / rate`，每秒只能取回 `storedMax/interval`。
   → 每个模块都隐含一个「满效间隔窗口」`I* = storedMax / rate`。

### 2.3 这才是有意思的地方

玩家面前永远是一道优化题：

```
想吃满 DPS  →  interval ≤ I*（否则溢出掉 DPS）
想省模块    →  interval 尽量长（但长过 I* 就开始掉 DPS）
```

短间隔 = 同样的 DPS、双倍的模块消耗。于是「省弹药」和「稳输出」天然对立，
而**提高 `I*`（更大 storedMax 或更低 rate）的模块，就是纯收益** —— 这是高阶模块的主要价值。

### 2.4 生存与成长条件

```
击杀率  kill/s = DPS / enemyHP
模块收入 drops/s = kill/s × 平均掉落数
模块支出 burn/s = 模块数 / (uses × interval)
```

| 条件 | 结果 |
|---|---|
| `drops/s < burn/s` | **死亡螺旋**：弹药库单调递减，伤害单调递减，必定死亡 |
| `drops/s ≈ burn/s` | 稳态：靠走位和手法续命，任何失误都会破防 |
| `drops/s > burn/s` | 成长期：可以拿多余模块去熔解升级 |

**这是本作的「血条」**：HUD 上永远显示模块净速率（如 `+0.42/s` 或 `−0.18/s`）。
玩家看到的不是血量在掉，而是**弹药库在掉** —— 这就是增量游戏最爽的负反馈。

### 2.5 基准数值表（v1 — M0 模拟标定，宽松成长）

> v0 的 `8 × 1.18^m` 已废弃。v1 由 `sim/economy_sim.gd` 用 20 分钟（30 波 × 40s）真实跑出来。
> 用户取向：**宽松成长**（玩家大部分时间正向成长，压力点稀疏但致命）。

| 参数 | v1 值 |
|---|---|
| 敌人 HP | `4 × 1.108^(wave−1)` |
| 刷怪率 | `0.9 + 0.02 × wave` 只/秒 |
| 每杀掉落 | 0.65 个基础模块 |
| 波间隔 | 40 s；20 分钟 30 波 |
| 插槽 | 4（初始）→ 5（wave 12）→ 6（wave 20），来自换更高品质武器 |
| 基础伤害 | 蓝 1.0 / 紫 1.5 / 金 2.0（不吃模块次数，模块烧光时的底） |
| 受击补偿 | 每损失 8 HP → 1 个模块（wave≥12 补加法，≥24 一次补 2 个；不发脉冲，它自身 0 出力） |
| 模块 | T1 `1.0 / 20次` · T2 `3.0 / 24次` · T3 脉冲 `0 出力 + 每3s 喂 9.0 / 28次` · T4 `27.0 / 34次` |
| 升级成本 | `3 × 1.18^(level−1)` 个模块 |
| 配方解锁 | 已改：不再按等级，全部靠升级四选一的第 4 张「解锁配方」逐个解锁（见 `docs/reference.md` §3.4）；下表是改版前的标定记录 |

| 波次 | 敌人 HP | 需求 DPS | 那时应有的构筑 | 状态 |
|---|---|---|---|---|
| 1 | 4.0 | 3.7 | 4 槽 T1 = 4 | 刚好 |
| 6 | 6.7 | 6.8 | 4 槽 T1/T2 ≈ 10 | 安全 |
| 10 | 10.1 | 11.1 | 4 槽 T2 = 12（T2 配方已解锁） | 临界 |
| 15 | 16.8 | 20.2 | 5 槽 T2 = 15 → 缺口，必须上 T3 | 危险 |
| 20 | 28.0 | 36.4 | 6 槽 T3 = 54 | 安全 |
| 25 | 46.6 | 65.2 | 6 槽 T3 = 54 → 缺口，必须上 T4 | 危险 |
| 30 | 77.6 | 116.4 | 6 槽 T4 = 162（Lv18 解锁 T4） | 收尾 |

**模拟结论**

- 掉落 0.45 → 末段余量 28%（实战会死）；0.55 → 131%；0.65 → ≈100%；0.75 → 109%。
  单种子抖动 ±30%，5 种子平均后 **0.65 是「宽松但有压力」的中心值**。
- **对 v0 的重要修正**：所有通关预设的模块净速率都是**正的**（+0.34 ~ +0.72/s）。
  也就是说本版数值下「净弹药率」不是硬失败条件，而是**节奏表（领先指标）**；
  真正的失败条件是 `DPS < 需求` → 场上敌人堆积 > 60。
  处理方式：HUD 仍主显净弹药率（它是玩家唯一能主动操控的杠杆），
  但死亡判定用战场压力。后续加精英波 / 围城 / 模块腐化等机制后，再把弹药真正做成稀缺资源。
- 阶梯必须是 **3× 一阶、4 阶**：需求 DPS 全程涨 35×，插槽只涨 1.5×，`35 / 1.5 ≈ 23 = 3^3`。
  把阶数改成 2× 或增减阶数都会破坏这个比例。


### 2.6 死亡螺旋的保底

纯负反馈会让新手 3 分钟就死。四层保险：

0. **武器基础伤害**：每把武器自带一个不吃模块次数的 `base`（蓝 1.0 / 紫 1.5 / 金 2.0），
   每次开火 `伤害 = base + Σ 槽位出力`。模块全烧光时 DPS 不归零，而是落到 `base / interval`，
   玩家仍能继续输出等掉落回填 —— 避免「弹药耗尽 → 屏幕完全不动 → 只能等死」的断崖。
1. **无目标不开火**：射程内没敌人不开火、不消耗次数 → 清场间隙是喘息窗口。
2. **空投补给**：每 60 秒地图上刷一个补给箱，按当前构筑给 2–3 个基础模块。
3. **濒死保护（每个 run 一次）**：弹药库归零时，冻结 3 秒并免费补 3 个基础模块（有冷却）。
   → 新手体验是「惊险」，而不是「莫名其妙就没了」。
4. **受击补偿（挨打换模块）**：每损失 8 HP 补 1 个模块（wave ≥ 12 补加法，≥ 24 一次补 2 个；不发脉冲，
   因为它自身 0 出力，当补偿发等于发了个空槽），
   掉在脚边被吸走。弹药系统让「打不出去」成为结构性劣势，所以掉血必须反哺构筑 ——
   越被压制、回填越快，把死亡螺旋改造成「越危险越肥」的翻盘窗口。

## 3. 模块系统

### 3.1 通用属性

每个模块：`tier / rate / uses / storedMax / 形状 / 配方 / 说明`

**熔解**：任意模块可拆成精华，收益 `= uses × rate × 0.5`，低于 3 精华的模块不可熔解。
→ 模块只有两条出路：**当子弹打掉，或当经验换成长**。这就是「多余模块」的定义。

### 3.2 模块表（v0）

> 状态：本节是 v0 的完整模块设想，**仅作历史参考**。线上已经是 plan-v5 的 **25 个模块 / 8 个族的科技树**
> （网络主干 + 锐化 / 冷却 / 弹链 / 穿甲 / 覆盖 / 维持 / 特化），配方改成「T2 吃 3 个基础，T3/T4 吃 2 个同族上一件」，
> 完整表见 [`reference.md`](reference.md) §3.3。电池、分流、冷凝没有做；脉冲被「增幅」吸收；熔解/精华也没有做。

| Tier | 名称 | rate | uses | storedMax | 效果 | 配方 | 解锁 |
|---|---|---|---|---|---|---|---|
| T1 | 基础 | 1.0 | 10 | 5 | 稳定的数值来源 | 掉落 | 初始 |
| T2 | **加法（镜像）** | 0 | 20 | — | 每个相邻的**更低级**模块，本次抽取**再加一份** | 2 基础 + 5 精华 | 工坊 L2 |
| T2 | 电池 | 0.5 | 30 | 40 | 超长缓冲，把 `I*` 拉到 80 秒（狙击流） | 3 基础 + 8 精华 | L2 |
| T2 | 增幅 | 0 | 15 | — | 整个 network 的 `raw ×1.3`（乘算） | 2 基础 + 12 精华 | L3 |
| T3 | **脉冲** | 0（充能 9.0） | 28 | — | 每 3s 把自身基础值加到**所有相邻的主动模块**上，加成永久留在对方身上（叠 9 跳封顶） | 2 加法 + 30 精华 | L4 |
| T3 | 分流 | 0 | 30 | — | 把本 network 30% 数值转给另一把武器 | 2 增幅 + 25 精华 | L5 |
| T4 | 共振 | 0 | 40 | — | 相邻同名模块互相 +50%（可叠 3 层） | 2 脉冲 + 60 精华 | L6 |
| T4 | 冷凝 | 1.5 | 12 | 4 | 极端 `rate`，只适合短间隔武器 | 2 电池 + 50 精华 | L6 |

设计要点：

- **加法模块只镜像「更低阶」的模块**。这条限制至关重要：
  它阻止「加法链自指 = 指数爆炸」，把每层增长锁在「本层数量 × 2」，成长靠**跨层**而不是靠堆同类。
- **加法模块按「份」线性叠加**：一个基础模块旁边放 3 个加法 = 4× 读数，不是 2³。
  玩家可以在同一层内做密排优化，但不能无限膨胀 —— 数值曲线可控。
- 每种模块占用**固定槽形**（1×1 / 1×2 / 2×2），槽位布局的几何形状因此产生真实约束。

### 3.3 工坊等级（半保留）

- 熔解模块获得精华 → 累积经验 → **工坊等级 L1..L10**。
- 每级解锁：新配方、全局增益（`rate +8%`、`uses +1`、掉落率 +5%）。
- **死亡后等级与精华保留 50%**（向下取整），配方永久解锁。
  → 单局内有推进感，跨局有长期积累；这也是唯一的「增量」持久层。

### 3.4 配方反查（Legibility）

构建屏必须显示「这个模块能做什么」：
`基础 ×2 + 精华5 → 加法`，以及「缺 1 个基础模块」的明确缺口提示。
增量游戏的死法是玩家看不懂数字，不是打不过。

## 4. 武器系统

### 4.1 武器属性

`形态 / interval / mul / 品质 / 槽位数量 / 槽位布局 / 特效`

形态决定「数值 → 伤害」如何落到战场上，这是除 `mul` 之外的第二层构筑：

| 武器 | interval | mul | 形态 | 特点 |
|---|---|---|---|---|
| 手枪 P-01 | 1.0s | 1.00 | 单体追踪 | 通用，浪费低 |
| 霰弹 S-12 | 1.4s | 0.22 ×5 弹 | 扇形 | 群体强，`mul` 低（吃的数值多） |
| 激光 L-03 | 2.0s | 1.60 | 穿透直线 | 打一排，对付密集纵列 |
| 环绕球 O-7 | 0.4s | 0.30 | 环绕 | 吃频率，模块烧得极快（弹药黑洞） |
| 链电 C-05 | 1.8s | 0.90 | 跳 3 个目标 | 对散兵群体 |

### 4.2 品质与槽位布局

品质**不提升数值**，只决定「你能摆多复杂的电路」：

| 品质 | 槽数 | 布局 | 构筑上限 |
|---|---|---|---|
| 白 | 2 | 直线 | 只能塞基础模块 |
| 绿 | 3 | 折线 | 基础 + 1 加法 |
| 蓝 | 4 | T 形 | 可做「1 源 2 镜」 |
| 紫 | 5 | 十字 | 可做「1 源 3 镜 + 电池」 |
| 金 | 6 | 双十字 | 可上 T3 脉冲，摆出「中心喂四周」 |

**核心槽**是唯一输出点：所有数值必须通过连接流到核心槽才会生效。
所以槽位布局是**电路板**，玩家在玩「走线」。

### 4.3 获取

- 精英怪（每 3 分钟）：35% 掉武器，品质抽签（白 60 / 绿 30 / 蓝 9 / 紫 1）。
- 地图宝箱（固定随机点位，小地图可见）：必出武器，品质略高。
- 金色宝箱（Boss 前）：必出紫及以上。
- 不提供「武器升级」—— 只有替换。**这保证了每一把新武器都是一次重新布线**，
  也是持续的构筑乐趣来源。

## 5. 战斗与关卡

- 单局 20 分钟，WASD 移动，自动索敌开火。
- 波次：每 3 分钟一次「潮」，每 5 分钟一个精英，20 分钟 Boss。
- 敌人原型：
  - 跑者（HP 低、速度快、成群）
  - 盾兵（有 `护甲` 阈值：单次伤害 < 护甲则该次伤害 ×0.2）→ 直接给「长间隔流」上强约束
  - 射手（远程，逼走位）
  - 分裂体（死亡分裂为 2 小怪 → 对群体伤害奖励）
  - 精英（掉武器）
- 走位空间是 L1 的全部；不要给闪避键，给「冲刺（2 次，冷却 3s）」即可。

## 6. 元游戏（增量层）

```
精华（跨局）
 ├─ 模块：rate +2%/级、uses +1/级（上限 10 级）
 ├─ 武器：起始品质提升、宝箱刷新 +1、精英掉落率 +
 ├─ 经济：掉落数 +5%/级、熔解保留率 50%→80%
 └─ 解锁：新武器蓝图、新模块配方
```

- 结算：`精华 = 击杀数 × 0.1 + 到达分钟数² × 2 + 剩余模块数`
- 第一次通关 20 分钟解锁**熔炉（Forge）**：重置局外进度换「核心」，全局倍率 ×1.5。
  → 经典增量转生，把 20 分钟的单局变成长期曲线。

## 7. UI / 交互

| 界面 | 做法 |
|---|---|
| 战斗 HUD | 顶部：弹药库净速率（带颜色）、DPS、存活时间、工坊等级；底部：武器条 |
| 构建屏 | **DOM 覆盖层**，不是 canvas（拖拽、tooltip、滚动列表都是 DOM 强项） |
| 槽位图 | 网格 + SVG 连线；连线在高亮时显示实时流量（每格 `+3.2/s`） |
| 实时预览 | 改动后立刻算：DPS、烧毁速率、净弹药率、预计存活时长 |
| 暂停策略 | 开构建屏时**时间冻结**；设置里可切「90% 慢放」（给硬核玩家） |

**节奏目标**：60–90 秒打一波 → 20–30 秒构建 → 循环。构建屏不该超过 30 秒，
所以必须提供「一键最优填充」按钮（把背包装进空槽的贪心解），让懒人也能玩。

## 8. 技术方案

**推荐：Vite + TypeScript + Canvas2D + DOM UI，无游戏引擎。**

理由：
- 本作 90% 的复杂度在**数值与 UI**，不在渲染。引擎（Godot/Phaser）会带来大量无用抽象。
- Canvas2D 画 500–1000 个几何体毫无压力（对象池 + 空间哈希）。
- 构建屏用 DOM，拖拽/tooltip/滚动全部原生解决。
- 纯逻辑与渲染分离 → 经济模型可以在 Node 里**无头模拟**、单元测试。

```
weapon-build-survivor/
├─ docs/design.md          # 本文档
├─ tasks/plan.md           # 实现计划
├─ src/
│  ├─ sim/                 # 纯逻辑，零渲染依赖
│  │  ├─ types.ts          # Module / Weapon / Slot / Network
│  │  ├─ module.ts         # 产出、抽取、镜像、烧毁
│  │  ├─ weapon.ts         # 开火结算、形态
│  │  ├─ economy.ts        # DPS / burn / margin（构建屏预览与测试共用）
│  │  ├─ enemy.ts          # 生成、HP 曲线、行为
│  │  └─ run.ts            # 单局状态机
│  ├─ render/              # canvas 2d
│  ├─ ui/                  # DOM 构建屏
│  ├─ data/                # 模块/武器/配方 JSON（可用表格配）
│  └─ meta/                # 存档、工坊等级
└─ tests/                  # vitest：经济公式、镜像、掉落平衡
```

- 固定步长 60Hz 逻辑 + rAF 渲染；`dt` 不参与数值结算（避免浮点漂移）。
- 存档：`localStorage` + 可导出的存档字符串。

## 12. v5 落地后与本文的差异（2026-10）

| 本文设想 | 实际实现 | 为什么改 |
|---|---|---|
| Vite + TypeScript + Canvas2D + DOM | Godot 4.7 + GDScript，HUD 用 `Control` 现搭 | 单场景原型迭代更快；DOM 那套要先搭一层壳 |
| 熔解模块换精华、工坊等级 L1–L10 | **没有做**；多余模块的出路是合成与升级 | 合成已经消耗掉溢出产能，再叠一层货币只是多一层 UI |
| 20 个模块、固定槽形 | **25 个模块、8 个族**，槽形统一 1×1，布局随机生成 | 固定槽形让「随机布局」没法做；族链让科技树能看懂 |
| 配方按工坊等级解锁 | **等级不解锁**，改成升级四选一的第 4 张「解锁卡」，只出前沿 | 工坊等级没做，需要一个新解锁口；顺带把 T4 前置变成「必须自己合出来」 |
| 模块烧完自动补料 | 人类**不自动补**：合成/拾取只进库存，装填是玩家的决定；可开「自动补料」只处理烧空 | 自动补料 = 玩家精心搭的板被系统改掉，比断料更伤 |
| — | **方案草稿 / 保存**：点格子只改草稿，保存才生效 | 让「先想好再执行」成为可能，避免手一抖就把板改了 |
| — | **拆卸 = 销毁**（板内互换保留） | 否则「拆下再装」等于白嫖重置寿命，寿命压力失效 |
| buff = 14 条，每条 3–8 层 | **24 族 × 4 品质 = 96 条独立变体**，每条 1–10 级，同次三张同品质 | 旧模型 20 级后全是垃圾卡；拆品质后每一抽都还有用 |
| 升级成本 `3 × 1.18^(level−1)` | 前 10 级同公式，**11 级起 ×1.12**（Lv30 365 → 125） | 旧曲线后期是指数墙，升级手感直接断掉 |
| 同屏 400 只 | **普通 ≤250 + 重装 ≤150**，两档各自判定 | 重装把名额吃光会让普通怪刷不出来 |
| 宝箱只能选或替换 | 还能**放弃换模块**（`2 + 品质` 个） | 背包满 + 四把都不想要时，需要一条出路 |

装填、模块表、buff 三块的完整规则见 [`reference.md`](reference.md) §3–§4；方案的取舍过程见 [`plan-v5.md`](plan-v5.md) §13。

## 13. v6 落地后的补充差异（2026-10-20，实机反馈驱动）

| 本文 / v5 的做法 | v6 实际实现 | 为什么改 |
|---|---|---|
| 升级成本 `3 × 1.18`（v5 改成 10 级后 ×1.12） | **`6 × 1.25^(level−1)`，8 级后 ×1.09** | 起价 3 太便宜，前 20 分钟升级像白送；陡增前 8 级让「攒料」变成真正决策 |
| 升级必须手动点 | 加**自动升级**开关（只扣料，不替人选卡） | 后期一局升三四十级，点升级变成体力活；选卡必须留给人 |
| 开局满板 base | **空模板**，只发 3 个基础模块 | 满板开局等于替玩家做了第一个构筑决定 |
| 装置吃模块背包 6 格、不能升级 | **独立装置背包**（起始 2 格，扩容 50 / 110 / 242 / 532）+ 装置 1–5 级 | 中后期一屏装置把武器挤没了；装置本身也该有成长线 |
| 模块「出力 N」，每次开火都吃满 | **「输出 N/Ns」**：每族有自己的 `out_iv`（0.6–2.4s）+ 蓄能条 | 「出力」看不出节奏；同一板在不同枪上表现一样，缺一个手感维度 |
| 激光环 420 射程、40s | **1600（全屏）** + 「激光充能」buff 直接减固定秒数（最低 6s） | 40 秒的「清场核弹」得真的清全场，否则不如换成小枪 |
| 冲锋枪 210 / 霰弹枪 200 | 冲锋枪 **360** | 两把枪射程几乎一样，定位撞车 |
| 敌人 HP `1.80 × 1.118^w` | **`2.40 × 1.135^w`，12 波后 ×1.050** | 装置变强 + 空模板后前期压力消失，整体上调约 ×1.3–1.7 |
| — | **`_check_data()`**：启动时校验 buff/模块表完整性并在 debug 下打印 | 一张表展开失败会让整局的关键面板哑掉，必须开一局就报错 |

手测清单见 [`plan-v6.md`](plan-v6.md) §11，实施记录见同文件 §12。

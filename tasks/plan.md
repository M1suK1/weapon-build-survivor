# 实现计划：Weapon Build Survivor

> 设计依据：`docs/design.md`。原则：**先证明经济模型成立，再证明手感成立，最后才堆内容。**

## 技术选型

- Vite + TypeScript（strict）+ Canvas2D + DOM UI，无引擎。
- Vitest 做纯逻辑测试（经济公式、镜像、掉落平衡）。
- 逻辑层 `src/sim` 零渲染依赖 → 可被 `tools/sim.ts` 无头复用。

## 架构决策

- **固定步长 60Hz**，`dt` 只用于累加器，数值结算按 tick 计数，避免浮点漂移。
- **逻辑/表现分离**：`sim` 只产出状态，`render` 只读状态。构建屏的数值预览与战斗内结算共用 `economy.ts` 的同一个函数（防止「预览说 12.4 DPS、实战打出 9」）。
- **模块网络**用邻接表表示（槽位 = 图节点，连接 = 边），核心槽为唯一 sink；加法模块是边上的修饰器，不是独立产出来源（避免结算顺序歧义）。
- **数据驱动**：模块/武器/配方/敌人全部 JSON（`src/data`），调数值不改代码。
- **测试先写经济**：`economy.ts` 在任何渲染代码之前完成并被单测覆盖。

## 任务表

### Phase 0：经济模型

- [ ] **T1 类型与数据骨架**
  - `src/sim/types.ts`：`ModuleDef / ModuleInstance / WeaponDef / Slot / SlotGraph / RunState`
  - `src/data/modules.json`、`weapons.json`、`enemies.json`（先用 design.md §3.2 / §4 的数值）
  - 验收：类型通过 `tsc --noEmit`，JSON 有 zod（或手写）校验
  - 验证：`pnpm typecheck`
  - 依赖：无 ｜ 规模：S

- [ ] **T2 经济函数与单测**
  - `src/sim/economy.ts`：`effectiveRate()`、`rawDraw()`（含镜像）、`dmgPerFire()`、`moduleBurnPerSec()`、`netModuleRate()`
  - `tests/economy.spec.ts`：手算用例（1 基础 = 10 单位输出；1 加法倍增；区间 > I* 时溢出衰减）
  - 验收：手算与实现一致；边界（0 槽、空网络）不崩
  - 依赖：T1 ｜ 规模：S

- [ ] **T3 无头模拟器**
  - `tools/sim.ts`：给定构筑与时间轴，输出 20 分钟曲线（DPS / 击杀率 / 净弹药率 / 工坊等级）
  - 验收：能产出 CSV 并在终端打印 ASCII 曲线；扫参（HP 增速、掉落数、uses）产出可行区间
  - 验证：`pnpm sim --minutes=20`
  - 依赖：T2 ｜ 规模：M

### Checkpoint A（M0 达成）

- [ ] `pnpm test` 全绿
- [ ] 模拟曲线在 0–20 分钟内净弹药率**不会自发崩盘**（不操作时缓慢下降，需要合成才能维持）
- [ ] 与设计文档的基准表（§2.5）误差 < 15%，否则改数值而不是改文档

### Phase 1：可玩切片（M1）

- [ ] **T4 游戏循环与渲染骨架**
  - `main.ts`：固定步长循环、canvas 尺寸/DPR、场景切换
  - `render/field.ts`：玩家、敌人、弹丸、掉落物（对象池 + 空间哈希）
  - 验收：800 敌人下 60fps，无 GC 抖动
  - 依赖：T1 ｜ 规模：M

- [ ] **T5 玩家与敌人**
  - WASD（+手柄可选）、冲刺（2 次/3s 冷却）、碰撞、受伤、无敌帧
  - 敌人原型：跑者/盾兵/射手，生成曲线来自 `enemies.json`
  - 验收：能被围死，也能拉开距离
  - 依赖：T4 ｜ 规模：M

- [ ] **T6 武器开火与模块结算**
  - 自动索敌 → 按 `interval` 开火 → 走 `economy.rawDraw()` → 伤害 → `uses--` → 烧毁
  - 敌人死亡掉落基础模块（自动吸附拾取，地面物上限合并）
  - 验收：模块烧毁可见、掉落能补充、HUD 净速率随状态实时变化
  - 依赖：T2、T5 ｜ 规模：M

- [ ] **T7 构建屏（核心体验）**
  - DOM 覆盖层：背包、槽位网格、SVG 连线、拖拽插入/交换、实时预览（DPS / burn / margin / 存活时间）
  - 打开即暂停；Esc 关闭；「一键最优填充」贪心按钮
  - 验收：纯鼠标 < 20 秒完成一次「换 3 个模块 + 合成 1 次」；预览值与实战一致
  - 依赖：T6 ｜ 规模：L（拆成 T7a 布局与拖拽 / T7b 预览计算 / T7c 一键填充）

- [ ] **T8 死亡与结算**
  - 弹药归零 → 濒死保护 → 死亡屏（击杀/分钟/最高 DPS/精华）
  - 验收：能从死亡回到主菜单并再开一局
  - 依赖：T6 ｜ 规模：S

### Checkpoint B（M1 达成）— 立项生死线

- [ ] 连续玩 5 分钟，观察：玩家是否主动打开构建屏？是否有「我再调一下」的冲动？
- [ ] 弹药净速率的 UI 是否被玩家理解（问 3 个人，能否说出「为什么我要换模块」）
- [ ] 若以上任一为否 → **回到设计层改，不要进入 Phase 2**

### Phase 2–4

- [ ] **T10** 5 把武器 / 5 品质布局 / 精英 / 宝箱 / Boss（M3）
- [ ] **T11** 精华、永久升级、存档、熔炉转生（M4）

## 风险与对策

| 风险 | 对策 |
|---|---|
| 构建屏太耗时，打断节奏 | Checkpoint B 设硬指标；达不到就砍成「自动装配 + 微调」 |
| 经济增长靠堆同类导致爆炸 | 数据层强制「只镜像低阶」，用 T2 校验 |
| 模拟器与实战数值不一致 | 预览与结算共用同一函数，T7b 加对拍测试 |
